Money Anywhere: Architecture ภาพรวม

แอป Android (Flutter) บอกผู้ใช้ว่าเงินที่ควรได้อยู่ที่ไหน ได้ประมาณเท่าไหร่ และพาไปรับจนจบ รวมถึงวางแผนรายได้ให้ถึงเป้ารายเดือน แอปคุยกับหลังบ้านผ่าน contract เดียว (contracts/openapi.yaml + app-config) หลังบ้านเป็น Node.js ที่ทุกการเชื่อมต่อภายนอกเป็น adapter สลับได้ด้วย env

49API operations ใน contract
10adapters สลับได้ด้วย env
139/139contract checks ผ่าน (26 พ.ย.)
16ไฟล์ Dart ใน app/lib

หลักการออกแบบ 6 ข้อ

1 Contract-first
แอปพึ่งแค่ openapi.yaml + app-config เปลี่ยนหลังบ้านได้โดยไม่แก้แอป
2 Ports & adapters
AI, ที่เก็บข้อมูล, แหล่งงาน, รัฐ, แจ้งเตือน สลับด้วย env หรือไฟล์เดียว
3 Rules as data
เกณฑ์และอัตราเงินอยู่ใน reference.json มีแหล่งและวันที่ตรวจ ผลคำนวณซ้ำได้
4 AI ไม่สร้างตัวเลขเงิน
ยอดมาจากกฎเท่านั้น guardMoney ลบตัวเลขที่ไม่มีที่มา การเขียนข้อมูลต้องให้ผู้ใช้ยืนยัน
5 ซื่อตรงกับข้อมูล
ทุกผลมี basis / dataStatus mock ติดป้าย ไม่มีผล verified จากกฎ
6 Demo ก่อน
ไม่มี login, การเข้ารหัส, rate limit ด้านความปลอดภัย ข้อมูลสังเคราะห์เท่านั้น

1เป้าหมายและขอบเขต

เป้าหมาย

  • บอกว่าเงินที่ผู้ใช้น่าจะมีสิทธิ์อยู่ที่ไหน ได้ประมาณเท่าไหร่ พร้อมเหตุผลและแหล่ง
  • ถามเฉพาะข้อที่ขาด แล้วคิดผลใหม่ทันที
  • สร้างแผนทีละขั้น ติดตามความคืบหน้า และผลที่ผู้ใช้แจ้ง
  • วางแผนรายได้ให้ถึงเป้ารายเดือนจากงานจริงและเวลาว่าง
  • ผู้ช่วย AI ที่อธิบายและพาทำ โดยไม่สัญญาเงิน

ไม่ทำ (Demo)

  • Login, การเข้ารหัส, rate limit ด้านความปลอดภัย, load test
  • ยืนยันตัวตนจริงและข้อมูลสิทธิ์รายบุคคลจากรัฐ (requirements ข้อ 9 Deferred; โหมดรัฐเป็น mock ซ่อนได้)
  • Publish store, production hosting
  • ข้อมูลคนจริง (repo เป็น public)

อ้างอิง: docs/product/requirements.md, aidlc/spaces/default/memory/project.md

6API design

ข้อตกลง

  • คำนามพหูพจน์; เปลี่ยนสถานะ task ผ่าน POST /v1/tasks/{id}/events ไม่ใช้ path แบบกริยา

8Flows หลัก

8.1 เช็คเงิน (ก่อนและหลังยินยอม)

8.2 ผู้ช่วย AI + ยืนยันก่อนเขียน

  1. แอป POST /v1/ai/conversations/{id}/messages (ต้องมี consent ai ไม่งั้นได้ skipped_no_consent)
  2. guard.js ตรวจก่อน: ถ้าเข้ากฎปฏิเสธ ตอบทันทีโดยไม่เรียก LLM (kind เช่น explain, skip, ai_scope)
  3. agent.js ให้ LLM เลือก tool; tool แบบ read (money, plans, goal) ทำทันที
  4. tool แบบเขียน (create_task, snooze_task, complete_step, update_facts) กลายเป็น PendingAction
  5. คำตอบผ่าน guardMoney: ตัวเลขเงินที่ไม่อยู่ในผล tool ถูกลบ
  6. ผู้ใช้กดยืนยัน → POST .../actions/{actionId} → ทำจริง; remember บันทึกเป็น MemoryItem ที่มองเห็นได้

8.3 แผนและการติดตาม

POST /v1/tasks → ขั้นตอนจากเส้นทางรับเงิน → POST /v1/tasks/{id}/events (complete_step, snooze, report_outcome; Idempotency-Key กันกดซ้ำ) → jobs.js ส่งเตือนทุกนาทีผ่าน notifier → แอปถามผลเมื่อผู้ใช้กลับจากลิงก์รัฐ → outcome reportedBy: user

8.4 แผนรายได้ตามเป้า

GET /v1/plans/goal: เป้ารายเดือน − เงินที่น่าจะได้ = ส่วนที่ขาด → jobOptions แปลงประกาศที่มีค่าจ้างเป็นช่วงรายเดือนตามเวลาว่าง → กรองตามทักษะที่ตรง (requires vs matched) และอายุ (forOlder ก่อน) → จำนวนตัวเลือกตามชั่วโมง (<15 = 1, 15–39 = 2, ≥40 = 3)

8.5 เชื่อม ThaID (mock)

flag govConnected (env GOV_CONNECTED=1) → consent gov → POST /v1/me/gov-link → POST /v1/me/gov-link/callback → gov.js คืน (1) identity: claims ชื่อตาม ThaID (given_name, family_name, birthdate, gender, address, date_of_expiry, ial …) ค่าสังเคราะห์, pidMasked + pidHash (เลขบัตรจริงไม่ออกจาก adapter) และ (2) data: บันทึกสิทธิ์จำลองต่อ persona (requires/skipIf) → server เติมโปรไฟล์ช่องที่ว่าง (ชื่อ, เขต) และช่วงอายุจากวันเกิด (Profile.fromGov) → ยกเลิกเชื่อมแล้วคืนค่าเดิม · ThaID ให้แค่ตัวตน ข้อมูลเงินต้องมาจาก API หน่วยงาน (GDX)

8.6 ดึงแหล่งงาน

jobs.js ทุก SOURCE_REFRESH_HOURS (ค่าเริ่ม 6) เมื่อ LIVE=1 → sources.js → normalize → dedupe (ชื่อ + องค์กร) → ตรวจลิงก์วันละครั้ง (404/410 ซ่อน) · พาร์ทเนอร์ push ผ่าน batch/webhook · รายงานจาก 3 เครื่อง → ซ่อนอัตโนมัติ

9Business logic

ผลของรายการเงิน

ผลเมื่อไหร่ยอด
likelyผ่านเกณฑ์ที่รู้ได้แสดงได้ (มี basis)
checkยอดขึ้นกับข้อมูลรัฐ / ผู้ใช้ตอบไม่แน่ใจไม่แสดง
needขาดคำตอบที่เปลี่ยนผลได้ไม่แสดง + คำถามถัดไป
unlikelyไม่ผ่านเกณฑ์ไม่แสดง + เหตุผล
verifiedเฉพาะ gov adapter จริง-

Basis / dataStatus

  • published_rate: อัตราที่ประกาศ
  • user_input: คำนวณจากที่ผู้ใช้กรอก
  • mock: จาก ThaID mock
  • ทุกรายการมี sources[{url, checkedAt}]

รายการเงินใน API

old_age, unemployment, child_support, disability, tax_refund, unpaid_wages (+ 19 รายการ planned ใน gov-services-inventory.md)

ลำดับถามคำถาม

แต่ละรายการบอก questions ที่ยังขาด เรียงตามลำดับที่เปลี่ยนผลได้มากที่สุดก่อน แต่ละ fact มี help และ short สำหรับคำอธิบายและป้าย ตอบ "ไม่แน่ใจ" ได้ (ผลเป็น check) และตอบ 0 ได้

Guard order (ผู้ช่วย)

กฎปฏิเสธชนะทุกอย่าง (injection, ขอข้อมูลอ่อนไหว, ขอการรับประกัน, มิจฉาชีพ/เงินกู้, นอกเรื่อง) → คำถามตรงเกี่ยวกับเส้นทางรับเงินตอบจากข้อมูล (DIRECT_RE) → ที่เหลือส่ง LLM · policy ไฟล์เดียว assistant-policy.json ใช้ทั้ง server และ mock

Privacyไม่มี consent ai → ไม่ส่งข้อมูลไป provider (skipped_no_consent) · ส่งได้แค่ persona สังเคราะห์ (free tier อาจใช้ข้อมูลปรับปรุงโมเดล)

18Decisions

การตัดสินใจเหตุผลทางเลือกที่ไม่เลือก
Flutter แอปเดียว, 4 แท็บ, โหมด ThaID ซ่อนหลัง govConnectedOwner ตัดสินแล้วสองแอป, React Native
Node.js ต่อยอดจาก mock serverผ่าน contract test ครบแล้ว เขียนใหม่ไม่เพิ่ม outputเขียนใหม่ด้วย framework อื่น
store แบบไฟล์ JSON ผ่าน portง่าย ไม่มีค่าใช้จ่าย เปลี่ยนเป็น Postgres ได้ด้วย adapter เดียวFirebase/Supabase เป็นหลังบ้านตรงจากแอป (แอปต้องรู้กฎเอง)
AI แบบ OpenAI-compatibleเปลี่ยนเจ้าด้วย envSDK ของเจ้าเดียว
เมนู/action จากหลังบ้าน (app-config)เปลี่ยนโดยไม่ออกแอปใหม่เขียนตายตัว (ตอนนี้ยังเป็นแบบนี้ในแอป)
รันบนโน้ตบุ๊ก + USBไม่หลับ ข้อมูลอยู่เครื่องเดียวRender free, tunnel
ThaID bypass + ป้าย DEMO / MOCKOwner สั่งให้ต่อได้ที่หน้าแรกซ่อน ThaID ตาม handoff (ขัดกัน บันทึกที่ M14)

20Glossary และ open questions

Glossary

  • Contract: openapi.yaml + app-config ที่แอปพึ่ง
  • Port / adapter: interface ภายใน / ตัวทำงานจริงที่สลับได้
  • Facts: คำตอบของผู้ใช้ที่ใช้คำนวณ
  • basis / dataStatus: ที่มาของตัวเลข / สถานะของแหล่ง
  • PendingAction: สิ่งที่ AI เสนอ รอผู้ใช้ยืนยัน
  • Persona: ผู้ใช้สมมติสำหรับ Demo

Open questions

  • ThaID ตอนพรีเซนต์: คง bypass + ป้าย หรือปิด GOV_CONNECTED
  • ระยะเวลาเก็บข้อมูล (RETENTION_DAYS) และผู้ติดต่อเรื่องข้อมูลส่วนบุคคล
  • จะย้ายไป hosting จริงไหมหลัง Demo (Postgres + host)
  • รายการเงินชุดไหนเข้า API ก่อน (แนะนำ: สงเคราะห์บุตร, ค่าคลอด, ค่าชดเชย, กอช.)
