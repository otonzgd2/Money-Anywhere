# โครงเมนูและลำดับความสำคัญของหน้าจอ (ร่าง)

> แอป Flutter ใช้ `docs/design/ui-states.md` เป็นตัวกำหนดว่าเมนู การ์ด และ popup ขึ้นเมื่อไหร่ ไฟล์นั้น §8 บอกจุดที่ต่างจากไฟล์นี้และ mock พร้อมเหตุผล

หลัก: ฟีเจอร์ครบได้ แต่สิ่งที่เห็นทันทีต้องน้อย ผู้ใช้หลักรวมผู้สูงอายุ จึงให้ 1 หน้ามีการกระทำหลัก 1 อย่าง ที่เหลือซ่อนไว้ชั้นที่สอง

## เมนูหลัก (แถบล่าง 4 แท็บ)
| แท็บ | หน้าที่เดียว | สิ่งที่ย้ายมาอยู่ข้างใน |
|---|---|---|
| 🏠 หน้าแรก | "ทำอะไรต่อ" | การ์ดขั้นต่อไป, ลิงก์งานอื่น, ลิงก์โอกาสใหม่, ลิงก์คุยกับ AI |
| ✨ โอกาส | "หาอะไรได้บ้าง" | รายการ ↔ แผนที่ (ปุ่มลอยปุ่มเดียว), ค้นหา, ตัวกรอง, แผนรายได้ |
| 📋 แผนของฉัน | "ที่บันทึกไว้และกำลังทำ" | ความคืบหน้า, เช็คลิสต์, อัปเดตสถานะ |
| 👤 ฉัน | "ตั้งค่าและช่วยเหลือ" | โปรไฟล์, ทักษะ, ตัวอักษรใหญ่, การเตือน, ข้อมูลของฉัน/ลบข้อมูล, แหล่งข้อมูล, วิธีใช้, รู้ทันมิจฉาชีพ |

เหตุผลที่ 4 แท็บ: แนวทางทั่วไปของแอปมือถือคือ 3-5 แท็บ ตั้งค่าเป็นแท็บที่มีชื่อชัดเจนหาง่ายกว่ารูปโปรไฟล์มุมจอสำหรับผู้สูงอายุ การบันทึกไว้รวมกับความคืบหน้าในแท็บเดียวแทนที่จะแยกแท็บ "รายการโปรด"

## หน้าโอกาส: เห็นทันทีเท่านี้
1. ช่องค้นหา + ปุ่ม "⚙️ ตัวกรอง" (มีตัวเลขบอกจำนวนตัวกรองที่เปิด)
2. ชิปหมวด 5 อัน เลือกได้ทีละอัน: ทั้งหมด, งาน, ทักษะ, ขายของ, เงิน/สิทธิ์
3. ผลลัพธ์ (รายการหรือแผนที่)
4. ปุ่มลอยสลับ "ดูแผนที่ / ดูรายการ"

ย้ายเข้า "ตัวกรอง": ระยะทาง, เรียงตาม, เฉพาะที่ระบุเงิน, แสดงประกาศน่าสงสัย, แหล่งข้อมูล
บนแผนที่เหลือ: ＋ / － / 📍 และป้ายตำแหน่งค้นหา (กดเพื่อเปลี่ยนเขต)

## ที่ตัดออกจากระดับแรก
| เดิม | ไปอยู่ที่ |
|---|---|
| ชิปบนแผนที่ 8 อัน | ชิปหมวด 5 อัน + ตัวกรอง |
| แถบรัศมี 1/3/5/10 | ตัวกรอง และปุ่ม ＋ / － |
| ปุ่มสลับรายการ/แผนที่ด้านบน | ปุ่มลอยด้านล่าง |
| ปุ่ม A+ และแถบโปรไฟล์บนหน้าแรก | แท็บ ฉัน |
| ปุ่มคุยกับ AI + เลือกเองบนหน้าแรก | ปุ่ม AI ใหญ่ปุ่มเดียว (Owner ให้เป็นจุดขาย ดู ui-states.md §3) เลือกเองอยู่ในแท็บ ฉัน > แก้ไขโปรไฟล์ |
| ชิปแหล่งข้อมูล | ตัวกรอง และแท็บ ฉัน |

## ผู้ใช้ใหม่: เริ่มจากเงินก่อน (ร่าง รอ Owner ยืนยัน)
เป้าหมาย: ภายในหน้าเดียว ผู้ใช้เห็นเงินของตัวเอง ยอด ที่ที่ต้องไป เอกสาร และแหล่งอ้างอิง

1. **เลือกเป้าหมาย** (`welcome`): การ์ดใหญ่ "💰 เช็คเงินที่ควรได้" เป็นค่าเริ่มต้น การ์ดเล็ก "🔎 หางาน" และ "🍳 รายได้จากทักษะ" ส่วนคุยกับ AI และกรอกโปรไฟล์เองย้ายเป็นลิงก์บรรทัดเดียว
2. **เช็คด่วน** (`quick`): ถามทีละข้อ เฉพาะข้อที่เปลี่ยนผล ข้ามได้ทุกข้อ ไปหน้าผลทันทีที่มียอดจากแหล่งให้โชว์ (ผู้สูงอายุ 3 ข้อ: อายุ บำนาญ ได้เบี้ยอยู่แล้วไหม; คนถูกเลิกจ้าง 4 ข้อ)
3. **สิ่งแรกที่ควรทำ** (`now`): 3 แท็บย่อย เงินที่ควรได้ / หางาน / จากทักษะ แต่ละแท็บมีการ์ดหลัก 1 ใบ + ทางสำรอง 1 ใบ
   - ไม่จัดอันดับข้ามแท็บ เพราะเงินสวัสดิการที่มีเกณฑ์ประกาศ งานที่ยังไม่รู้ว่าเปิดอยู่ และการทดลองขายของ วัดด้วยเกณฑ์เดียวกันไม่ได้
   - ในแท็บเดียวกันเรียงตามความแน่นอนของการกระทำ (มียอดจากแหล่ง > น่าจะมีสิทธิ์ > ต้องเช็คยอด > ต้องตอบเพิ่ม) ไม่ใช้ "โอกาสได้เงิน"
   - หางาน: ถ้ายังไม่มีประกาศจริงที่ตรวจแล้ว บอกตรงๆ และติดป้าย DEMO / MOCK ทุกใบ มีสำนักงานจัดหางานเป็นทางที่ใช้ได้เสมอ และโชว์เงินว่างงานถ้าน่าจะมีสิทธิ์
   - จากทักษะ: ติดป้าย "ประมาณการ" และ "ยังไม่มีผู้ซื้อยืนยัน" การกระทำแรกคือร่างข้อความรับออเดอร์ไปทดลองกับคนรู้จัก
   - ไม่พบอะไร: บอกว่ายังไม่พบ พร้อมข้อที่ยังไม่ได้ตอบ ไม่เติมรายการแทน
4. **หน้าแรกผู้ใช้เดิม**: มีขั้นค้างก็แสดงขั้นต่อไปเหมือนเดิม ถ้าไม่มี แสดงการ์ด "สิ่งแรกที่ควรทำ" แทน "ไม่มีงานค้าง"
5. **กลับจากลิงก์ภายนอก**: ถามว่า "สมัคร/ยื่นแล้วหรือยัง" เมื่อผู้ใช้กลับเข้าแอปจริงเท่านั้น และบันทึกเป็น "ผู้ใช้แจ้ง"

6. **ได้เงินอยู่แล้ว**: ถามว่าได้เบี้ยผู้สูงอายุอยู่แล้วไหม ถ้าได้ ไม่นับเป็นเงินใหม่และไม่ขึ้นเป็นสิ่งแรกที่ควรทำ แสดงเป็น "ตรวจยอดให้ครบ" พร้อมขั้นบันไดถัดไป แล้วถามต่อเพื่อหาเงินก้อนอื่น
7. **ครอบคลุมคนวัยทำงาน**: เพิ่มเงินอุดหนุนเด็ก (600) และเบี้ยความพิการ (800 + 200 ถ้ามีบัตรสวัสดิการ) ในการเช็คด่วน
8. **PDPA**: เช็คด่วนไม่บันทึกอะไร จึงไม่ต้องขอความยินยอมก่อนเริ่ม ขอเมื่อกด "บันทึกเป็นแผน"

หลังบ้านที่ใช้ (API 0.6 ตรงกับ mock แล้ว):
- เช็คด่วนก่อนยินยอม: `POST /v1/money/preview` (ไม่บันทึก ไม่ต้องมี X-Device-Id) คืน `nextQuestion` ให้ถามข้อต่อไป
- รายการ `child_support`, `disability` และ `alreadyReceiving` ("ได้อยู่แล้ว") อยู่ใน `reference.json` แล้ว
- หลังกดบันทึกแผน: `POST /v1/me/consents` แล้ว `PATCH /v1/me/facts`, `POST /v1/tasks`
- ปุ่ม AI: `POST /v1/me/consents` (core + ai) แล้ว `POST /v1/ai/conversations` (`mode: guided`)
- id ใน mock ยังต่างจาก API (`old`/`old_age`, `child`/`child_support`, `disab`/`disability`, `unemp`/`unemployment`, `tax`/`tax_refund`, `owed`/`unpaid_wages`) ให้ Flutter ใช้ id ของ API (TB.20)

## ข้อควรตรวจเมื่อทำของจริง
- ทดสอบกับผู้ใช้จริงอย่างน้อย 3 คน (รวมผู้สูงอายุ) ว่าหางานค้างและเปลี่ยนตัวอักษรได้เองโดยไม่ต้องบอก (สมมติฐาน ยังไม่ได้ทดสอบ)
- ขนาดเป้ากดอย่างน้อย 48 dp ตามแนวทาง Material
