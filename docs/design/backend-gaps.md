# Backend Gap Analysis (หลัง API v0.2)

ตรวจหลังบ้านเทียบกับ `docs/product/requirements.md` (FR-01..08, AC-01..07, ข้อ 5-7) และสิ่งที่ backend ต้องมีเพื่อใช้งานจริง
ระดับ: **P0** = ไม่มีแล้วผ่าน AC/Demo ไม่ได้, **P1** = ต้องมีก่อนให้คนอื่นใช้นอกเครื่องทีม, **P2** = ทำทีหลังได้

## A. ขาดเทียบกับ requirements
| # | ขาด | อ้างอิง | ระดับ | ตอนนี้เป็นอย่างไร | ต้องเพิ่ม |
|---|---|---|---|---|---|
| A1 | กฎตรวจสิทธิ์เบื้องต้นแบบมีเวอร์ชัน (เช่น อายุถึงเกณฑ์เบี้ยผู้สูงอายุไหม) | ข้อ 6 "versioned, testable business rules", Track A | P0 | ไม่มี ทุกคนเห็นรายการ track A เหมือนกัน และ profile ไม่มีช่วงอายุ | `eligibility_rules` มีเวอร์ชัน, `POST /v1/eligibility/checks` ตอบ `likely / unlikely / unknown` + ข้อมูลที่ขาด, ห้ามตอบว่า "มีสิทธิ์แน่นอน" และเพิ่ม `ageRange` ใน profile |
| A2 | ไอเดียรายได้จากทักษะ | Track C, FR-04 | P0 | แผนรายได้เป็นไฟล์ตายตัว 7 รายการ ไม่ขึ้นกับทักษะของผู้ใช้ | AI port เพิ่ม `suggestIdeas(profile)` ติดป้าย AI inference ตัวเลขต้นทุนเป็น estimate + fallback เป็นรายการไอเดียตามกลุ่มทักษะใน reference |
| A3 | แผนรายได้คำนวณจากข้อมูลจริงของผู้ใช้ | FR-04 | P0 | ใช้ fixture ไม่ได้คิดจากค่าจ้างในประกาศ x ชั่วโมงว่างของผู้ใช้ | คำนวณจาก `Money` ของโอกาส + `hoursPerWeek` + ต้นทุนตามหมวด ส่งสมมติฐานออกมาทุกครั้ง |
| A4 | AI ช่วยทำความเข้าใจโปรไฟล์จากข้อความอิสระ | FR-01 "AI Profile" | P0 | intake ใช้สคริปต์ 5 ข้อ เก็บคำตอบดิบ ไม่ผ่าน AI | AI port เพิ่ม `extractProfile(text)` แปลงคำตอบอิสระเป็นฟิลด์ profile + fallback สคริปต์เดิม |
| A5 | เรียก AI จริงอย่างน้อยหนึ่งเส้นทาง | AC-02 | P0 | มี adapter แต่ยังไม่มี key ทุกอย่างตอบ `fallback_rules` | เลือก provider ใส่ key ใน env และบันทึกผลเรียกจริง |
| A6 | หลักฐานผูกกับ commit | AC-05 | P0 | ไม่มีทางรู้ว่า server ที่รันอยู่มาจาก commit ไหน | `GET /v1/health` คืน version, commit SHA, เวลา start, สถานะ AI/แหล่งข้อมูล |
| A7 | ช่องทางทางการต่อหมวด | ข้อ 6 "identified official/provider channel", FR-05 | P0 | มีแค่ `sourceUrl` ของประกาศ ไม่มีชื่อหน่วยงาน เบอร์โทร หรือช่องทางยืนยันสิทธิ์ | `officialChannels` ใน reference ต่อหมวด (ชื่อ, URL, เบอร์) และผูกกับโอกาส |
| A8 | บันทึกผลลัพธ์ที่ผู้ใช้แจ้ง (ได้งาน/ไม่ได้, ได้เงินเท่าไหร่) | FR-06 "track actions and outcomes" | P1 | Task มีแค่ขั้นตอน ไม่มีผลลัพธ์ | event type `report_outcome` มี `result` และ `amountReported` ติดป้ายผู้ใช้แจ้ง |
| A9 | ตรวจลิงก์ต้นทางเสียหรือประกาศหมดอายุ | AC-04 "stale/invalid sources" | P1 | กรองเฉพาะ `expiresAt` ไม่ได้ตรวจว่า URL ยังเปิดได้ | งานตามรอบตรวจ URL แล้วตั้ง `linkStatus` และซ่อนหรือเตือน |
| A10 | ข้อมูลซ้ำข้ามแหล่ง และข้อมูลที่ขัดกัน | FR-08 "contradictory data" | P1 | ประกาศเดียวกันจากสองแหล่งจะขึ้นสองรายการ | dedupe key (ชื่อ+องค์กร+URL) และ flag `conflict` เมื่อตัวเงินหรือเงื่อนไขต่างกัน |
| A11 | คำแนะนำเมื่อไม่พบผล | FR-08 "no matching opportunities" | P1 | คืนรายการว่างเฉยๆ | คืน `suggestions` เช่น ขยายรัศมี เปลี่ยนหมวด หรือเปิด onlyMoney |
| A12 | ชุดผู้ใช้สมมติสำหรับสาธิต | AC-01 | P1 | ต้องกรอกเองทุกครั้ง | `POST /v1/demo/personas/{id}` โหลดโปรไฟล์และงานตัวอย่าง (เปิดได้เฉพาะ demo mode) |
| A13 | จัดการรายงานประกาศน่าสงสัย | FR-07 | P2 | รายงานเก็บไว้เฉยๆ ไม่มีใครเห็น | ซ่อนอัตโนมัติเมื่อรายงานถึงเกณฑ์ + endpoint ให้ทีมดู (ใช้ X-Api-Key) |

## B. ขาดในฐานะ backend ที่ใช้งานจริง
| # | ขาด | ระดับ | ตอนนี้ | ต้องเพิ่ม |
|---|---|---|---|---|
| B1 | ที่เก็บข้อมูลถาวร | P0 | หน่วยความจำ ปิด server แล้วหาย | เลือก DB (TB.6) + migration + ข้อมูลตั้งต้น |
| B2 | ที่รัน server ที่มือถือเข้าถึงได้ | P0 | รันบนเครื่อง dev เท่านั้น (emulator ต้องใช้ `10.0.2.2`) | host ฟรีหรือ tunnel สำหรับสาธิต + Dockerfile หรือสคริปต์ deploy |
| B3 | งานตามรอบ (scheduler) | P1 | ดึงข้อมูลเฉพาะตอนเปิดหรือกด refresh, การแจ้งเตือนไม่ถูกส่งจริง | job: ดึงแหล่งข้อมูลทุก N ชั่วโมง, ส่งเตือน, ตรวจลิงก์, ล้างข้อมูลหมดอายุ |
| B4 | คุมค่าใช้จ่าย AI | P1 | ไม่มีเพดาน | จำกัดจำนวนเรียกต่อเครื่องต่อวัน, cache ผลจัดอันดับตาม profile+รายการ, เพดานรวมต่อวัน (ไม่ใช่งาน security แต่กันบิลบานปลาย) |
| B5 | log และหลักฐาน | P1 | ไม่มี log | log แบบมีโครงสร้างผูก `requestId`, เก็บ `ai_invocations` (เวลา, provider, สถานะ, ไม่เก็บข้อมูลส่วนตัว) และ export เป็นหลักฐานได้ |
| B6 | แยก environment | P1 | ค่าคงที่ในโค้ด, CORS เปิดทุกที่ | env สำหรับ local / demo, ไฟล์ `.env.example` ครบทุกตัวแปร |
| B7 | client SDK สำหรับ Flutter | P1 | U1 ต้องเขียนเรียก API เอง | generate Dart client จาก `openapi.yaml` และใส่ในขั้นตอน `npm run check` |
| B8 | เผยแพร่ config เวอร์ชันใหม่และย้อนกลับ | P2 | อ่านจากไฟล์ตรง | เก็บ config หลายเวอร์ชัน เลือกใช้ได้ ย้อนกลับได้ |
| B9 | CHANGELOG ของสัญญา | P2 | ไม่มี | บันทึกการเปลี่ยนแต่ละเวอร์ชัน และกติกาการ deprecate |
| B10 | ระยะเวลาเก็บข้อมูล | P2 | ไม่ได้กำหนด | กำหนดว่าเก็บข้อมูลผู้ใช้และ log นานเท่าไหร่ |

## C. ที่ตั้งใจไม่ทำ (ตามกฎโปรเจกต์ Demo)
- ระบบล็อกอิน การเข้ารหัส rate limit ด้านความปลอดภัย และ load test (`project.md` ระบุไม่ทำสำหรับ Demo) ใช้ `X-Device-Id` แทน ซึ่งปลอมได้ ยอมรับได้สำหรับ Demo เท่านั้น
- รายการ Deferred ใน requirements ข้อ 9

## D. บั๊กที่เจอระหว่างตรวจ
- อายุข้อมูล (`ageDays`) คำนวณครั้งเดียวตอนโหลด server ที่เปิดค้างไว้หลายวันจะบอกอายุผิด **แก้แล้ว** คำนวณตอนอ่านทุกครั้ง test ยังผ่าน 45/45
