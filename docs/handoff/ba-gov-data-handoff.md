# Handoff ให้ BA: ข้อมูลภาครัฐและหลังบ้าน ทำได้แค่ไหน

สถานะ: ยืนยันแล้ว 26 พ.ย. 2569 (API 0.10.0, contract test 139/139, mockup บริการรัฐ smoke 37/37)
ใช้ทำ: สรุป UI ต่อ ไฟล์นี้ตอบแค่คำถามเดียว "หลังบ้านให้ข้อมูลอะไรได้ ระดับไหน"
รายละเอียดเต็ม: `docs/design/gov-services-inventory.md` · หน้าจอทดลอง: `docs/mockups/gov-services.html` (เปิดในเบราว์เซอร์ได้เลย) · API: `docs/backend/index.html`

## 1. คำตอบสั้น
- **ไม่มีข้อมูลรัฐรายบุคคลแบบสดเลย** ThaID และ GDX ต่อจริงไม่ได้ในช่วง Demo (ต้องมีข้อตกลงกับหน่วยงาน)
- หลังบ้านบอกได้ว่า "คุณน่าจะมีสิทธิ์อะไร ได้ประมาณเท่าไหร่ ไปยื่นที่ไหน ต้องเตรียมอะไร" จาก **เกณฑ์และอัตราที่ประกาศ + คำตอบของผู้ใช้**
- ยืนยันผลจริงทำได้ทางเดียว: ผู้ใช้ไปเช็คในแอป/เว็บรัฐ แล้วกลับมาบอกผล (บันทึกเป็น "คุณแจ้ง")
- ThaID ในแอปเป็น **ข้อมูลจำลอง** กดเชื่อมได้ แต่ต้องติดป้าย DEMO / MOCK ทุกที่

## 2. ระดับข้อมูลที่ UI ต้องแยกให้เห็น
| ระดับ | มาจาก | UI แสดงได้ | ป้าย/ข้อความ |
|---|---|---|---|
| 1 อัตราที่ประกาศ | เกณฑ์สาธารณะใน `reference.json` | ยอดเงินได้ | "ตามอัตราที่ประกาศ ยังไม่ได้ยืนยันสิทธิ์ของคุณ" |
| 2 คำนวณจากที่ผู้ใช้กรอก | ค่าจ้าง อายุงาน ฯลฯ | ยอดเงินได้ | "คำนวณจากตัวเลขที่คุณกรอก" |
| 3 ต้องเช็คยอดจริง | ยอดขึ้นกับข้อมูลรัฐที่เราไม่มี | **ไม่แสดงยอด** แสดงปุ่มพาไปเช็ค | "ต้องเช็คยอดจริง" |
| 4 ผู้ใช้แจ้ง | ผู้ใช้กลับมาบอกผล | สถานะ ได้แล้ว/ไม่ผ่าน/ยังไม่ทำ | "คุณแจ้งว่า..." |
| 5 ข้อมูลจำลอง | ThaID mock, ประกาศงาน mock, จุดบริการบนแผนที่ | ได้ แต่ห้ามดูเหมือนของจริง | DEMO / MOCK |
| - ยืนยันจากหน่วยงาน | ต้องเชื่อมรัฐจริง | **ทำไม่ได้ใน Demo** | - |

ผลต่อรายการมี 4 แบบ: น่าจะได้ / ต้องเช็คยอดจริง / ตอบอีกข้อ / ไม่น่าได้ ห้ามใช้คำว่า "ได้แน่นอน" หรือ "ยืนยันแล้ว"

## 5. ช่องทางรัฐที่ UI ต้องมีปุ่มพาไป (ไม่มีการเชื่อม API)
ทางรัฐ · เป๋าตัง · ประกันสังคม e-Self Service / 1506 · empui.doe.go.th (ว่างงาน) · My Tax Account · แอปเงินเด็ก · แอป กอช. · LINE @OICConnect · แอป Wiset · welfare.mof.go.th · สำนักงานใกล้บ้าน (แผนที่)

รูปแบบเดียวกันทุกช่องทาง: บอกว่าจะเปิดอะไร → บอกว่าต้องกดเมนูไหน → เตือน "รัฐไม่ขอ OTP" → กลับมาแล้วถามผล

## 6. สิ่งที่ UI ต้องออกแบบเพิ่ม เพราะไม่มีข้อมูลรัฐ
1. **หน้าความพร้อม**: ผู้ใช้มี ThaID, พร้อมเพย์ผูกเลขบัตร, เป๋าตัง, บัญชีประกันสังคม, บัญชีสรรพากร, LINE หรือยัง (เงินน้ำท่วมโอนไม่ได้ถ้าไม่ผูกพร้อมเพย์กับบัตร)
2. **ทางเข้าด้วยเหตุการณ์ชีวิต** 10 แบบ เพราะผู้ใช้ไม่รู้ชื่อโครงการ
3. **ถามผลเมื่อกลับมา** จากแอปรัฐ เป็นทางเดียวที่ได้ผลจริง
4. **ป้ายระดับข้อมูล** ตาม §2 ในทุกการ์ดเงิน
5. **ป้ายร่างกฎหมาย** สำหรับสิทธิ์ใหม่ในร่าง พ.ร.บ.ประกันสังคม (ยังไม่มีผล ห้ามแสดงว่าใช้ได้)

## 7. ทำไม่ได้ใน Demo
- ดึงยอดเงินจริงของผู้ใช้จากรัฐ (สถานะเบี้ยยังชีพ ยอดประกันสังคม ยอดคืนภาษี)
- ยืนยันตัวตนด้วย ThaID จริง
- รู้ว่าบ้านผู้ใช้อยู่ในพื้นที่ประกาศภัยไหม (ต้องถาม)
- ที่ตั้งสำนักงานจริงบนแผนที่ (ตอนนี้จำลอง กำลังดู OSM ฟรี)

## 8. เรื่องที่ยังไม่ชัวร์ (กระทบตัวเลขบนจอ)
ดู `docs/plan/open-items.md` D13-D19 ที่กระทบ UI ตรงๆ:
- สงเคราะห์บุตร 1,000 หรือ 800 (D13) ใช้ 1,000 ตามโฆษก ก.ค. 2569
- วันปิดรับเงินน้ำท่วม (D17) ยังไม่รู้ UI ต้องรองรับ "วันปิดยังไม่ประกาศ"
- ชื่อเมนูในทางรัฐ/เป๋าตัง (D19) ยังไม่ได้เปิดแอปจริงดู

## 9. BA ต้องตัดสินใจ / ส่งกลับ
- เลือกรายการที่จะโชว์ใน Demo (แนะนำ: เบี้ยผู้สูงอายุ, ว่างงาน, สงเคราะห์บุตร+ค่าคลอด, ค่าชดเชยเลิกจ้าง, กอช., กรมธรรม์ที่ลืม)
- หน้าความพร้อมอยู่แท็บ ฉัน หรือขึ้นก่อนเปิดลิงก์อย่างเดียว
- เหตุการณ์ "คนในครอบครัวเสียชีวิต" จะโชว์ใน Demo ไหม (ข้อมูลอ่อนไหว)
