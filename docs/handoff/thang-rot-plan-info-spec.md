# ข้อ 7 รายการแผน หน้า Info และข้อมูลติดต่อ

**แผนของฉัน → เลือกรายการ → รายละเอียดแผน → ข้อมูลติดต่อ** กดย้อนกลับจากข้อมูลติดต่อแล้วกลับมาที่แผนเดิม โดยไม่เปิดเว็บไซต์หรือเปลี่ยนความคืบหน้าเอง

ใช้หน้า Info โครงเดียวทั้งสิบหมวดและสลับส่วนข้อมูลสรุปได้ 4 แบบ ใช้หน้าข้อมูลติดต่อร่วมกันทุกหมวด ผู้ใช้ยังเข้าถึงสถานะ ขั้นตอน เอกสาร ลิงก์ต้นทาง และหน้าวิธียื่นของแผนเดิมได้ ข้อมูลเฉพาะของแต่ละหมวดแยกอยู่ในส่วนที่มีหัวข้อชัดเจน

[เปิด DEMO HTML พร้อมตัวอย่างสิบหมวด](../mockups/index.html#plan-demo)

## เทียบกับหน้าที่มีในระบบ

| ตัวอย่างเดิม | เก็บไว้ | ปรับในข้อ 7 |
| --- | --- | --- |
| หน้ารายการแผนและ `TaskScreen` | ชื่อ สถานะ ความคืบหน้า ขั้นปัจจุบัน ติดปัญหา ไว้ทีหลัง ย้อนขั้น และแจ้งผล | ให้ปุ่มข้อมูลติดต่ออยู่ใต้ชื่อ ใส่ป้ายหมวดและสรุปสำคัญ แล้วแบ่งความคืบหน้า เงื่อนไข เอกสาร และแหล่งข้อมูลเป็นหัวข้อ |
| หน้า Info ในไฟล์อ้างอิงกรุงเทพฯ | ชื่อรายการ สีตามหมวด กล่องสรุป ผู้เผยแพร่ เงื่อนไข และที่ตั้งที่มีหลักฐาน | ให้หมวดกำหนดรูปแบบและป้าย คงชื่อแผนกับบริบทเขตข้ามหน้าข้อมูลติดต่อ โดยไม่สร้างหน้าใหม่สำหรับแต่ละหมวด |
| `RouteScreen` และ DEMO สิทธิ์ | เอกสาร วิธีและสถานที่ยื่น แหล่งอ้างอิง และติดตามผล | ย้ายช่องทางไปหน้าติดต่อ และคงทางเข้า **ดูวิธียื่นและติดตามผล** สำหรับรายการเงิน |
| `OpportunityContactScreen` และ DEMO สมัครงาน | ลิงก์ประกาศต้นทางและตัวอย่างงานที่แสดงชื่อรายการจริง | ให้ผู้ใช้เห็นช่องทางและกดเปิดเอง งานตัวอย่างใช้ปุ่มที่ระบุว่าเป็นตัวอย่าง เมื่อประกาศหายให้แสดงสถานะและทางกลับ |

โครงหน้าเดิมอยู่ใน [UI states](../design/ui-states.md) และ [HTML อ้างอิงหน้า Info](../mockups/bangkok-opportunity-scope.html) การแบ่งตามการกระทำของผู้ใช้ต่อยอดจาก [แหล่งข้อมูล 10 หมวด](../product/thailand-job-data-sources.md#7-แนวทางตามหมวดโอกาส-10-หมวด) ซึ่งจัดทุนร่วมกับสิทธิ์ในสายข้อมูลเดิม หน้านี้ให้ทุนมีรูปแบบของตัวเอง เพราะผู้ใช้ต้องเห็นรอบทุนและวันปิดรับก่อนตัดสินใจ

## หน้ารายการแผนตาม DEMO ล่าสุด

ใช้รูปแบบจาก [DEMO หน้าแผนที่มีรายการ](../mockups/index.html#plan-demo) เป็นแบบสำหรับแท็บ **แผนของฉัน** ใน Flutter เมื่อต้องเทียบกับหน้าว่าง ให้เปิดแท็บใน DEMO ก่อนโหลดแผนตัวอย่าง [ภาพหน้าที่มีรายการ](thang-rot-assets/plan-list-reference.png) · [ภาพหน้าว่าง](thang-rot-assets/plan-list-empty-reference.png)

| ส่วน | พฤติกรรมและข้อมูล |
| --- | --- |
| Header | แสดง **แผนของฉัน** เป็นหัวข้อเดียว พื้นเขียวเข้มมุมล่างโค้งตาม DEMO เมื่อมีรายการให้แสดง **N แผนที่บันทึก** ใต้ชื่อ นับจากแผนที่โหลดและแสดงจริง เมื่อหน้าว่างหรือกำลังโหลดให้แสดงชื่ออย่างเดียว |
| พื้นและการ์ด | ใช้พื้นหลังเขียวเทาอ่อน การ์ดสีขาวมีเส้นขอบบาง มุมโค้ง และระยะห่างสม่ำเสมอ การ์ดกดได้ทั้งใบ มีลูกศรที่ชื่อรายการ และใช้แถบนำทางเดิมของแอป |
| ข้อมูลในการ์ด | แถวแรกมีหมวดฝั่งซ้ายและป้ายสถานะฝั่งขวา ตามด้วยชื่อแผน **ขั้นถัดไป** และเส้นความคืบหน้าบางพร้อม **X/Y ขั้น** ใช้ข้อความระบุสถานะร่วมกับสี แผนสาธิตที่มีอยู่ต้องยังแสดงป้าย Demo ตามแหล่งเดิม |
| กลุ่มสถานะ | เรียง **กำลังทำ** → **รอดำเนินการ** → **เสร็จแล้ว** กลุ่มรอดำเนินการรวม `blocked` และ `snoozed` โดยเรียง **ติดปัญหา** ก่อน **เลื่อนไว้** แสดงหัวข้อกลุ่มเมื่อมีมากกว่าหนึ่งกลุ่มที่มีรายการ หากสถานะยังไม่รู้จักให้แสดงรายการท้ายสุดพร้อมคำว่า **ไม่ระบุสถานะ** |
| สถานะว่างและรอโหลด | เมื่อโหลดสำเร็จและไม่มีแผน ให้แสดง **ยังไม่มีแผน** พร้อมปุ่ม **ไปเช็คเงินที่หน้าแรก** ปุ่มโหลดตัวอย่างสิบหมวดใช้สำหรับ HTML DEMO ระหว่างโหลด และเมื่อเกิดข้อผิดพลาด ให้ใช้ตัวเตือนและปุ่มลองใหม่ตามพฤติกรรมเดิม หากบางแหล่งยังโหลดได้ ให้แสดงรายการที่ได้พร้อมแจ้งข้อผิดพลาด |
| การเข้าถึง | ใช้พื้นที่กดทั้งการ์ด ให้ชื่อ สถานะ ขั้นถัดไป และตัวเลขความคืบหน้าอ่านได้เมื่อขยายตัวอักษร คืนตำแหน่งรายการเมื่อย้อนกลับจากรายละเอียดแผน |

รายละเอียดภาพอ้างอิงใช้ header `#163E35` ให้ข้อความสีขาว พื้นหลัง `#F3F7F4` การ์ดขาวขอบ `#DCE7DF` มุมประมาณ 15 dp ใช้สีหมวดผ่าน `OpportunityCategory` และเทียบรูปแบบกับส่วน `plan-list-header` และ `plan-item` ของ HTML เครื่องหมายสถานะแบตเตอรี่ ขอบเครื่อง และป้ายควบคุมตัวอย่างอยู่ในกรอบสาธิต

ใช้ข้อมูลจาก `GET /v1/tasks` และเส้นทาง `PlansTab → TaskScreen` ที่มีอยู่ แสดง **ขั้นถัดไป** จาก `steps[doneCount]` เมื่อดัชนีอยู่ในช่วงและสถานะยังไม่เสร็จสิ้น ซ่อนตัวอย่างขั้นเมื่อไม่มีขั้นให้ทำต่อ ถ้ามีขั้น ให้จำกัดค่าความคืบหน้าที่แสดงในช่วงศูนย์ถึงจำนวนขั้น ข้อความใต้รายการใช้ **สถานะและความคืบหน้าอิงจากที่คุณแจ้ง**

อ่านหมวดจาก `category` หรือ `categoryId` เมื่อ API มีค่า ใช้ `OpportunityCategory.forMoney` กับแผนเงิน หากแผนเก่ายังไม่มีหมวด ให้แสดงการ์ดและเปิดรายละเอียดได้ตามปกติ สำหรับประกาศงานและโอกาสที่หมวดยังไม่มากับ TaskList ให้เติมหมวดเป็น metadata แบบเลือกได้จากแคตตาล็อกเดิมใน response เพื่อให้หมวดแสดงพร้อมรายการ การปรับนี้ใช้ข้อมูลเดิมและใช้ได้โดยไม่มี DB ใหม่

## หน้ารายละเอียดแผนและข้อมูลติดต่อ

หน้า **รายละเอียดแผน** แสดงป้ายหมวด สถานะรายการ ชื่อ ผู้เผยแพร่หรือหน่วยงาน ยอดหรือค่าตอบแทนตามข้อมูลที่มี และปุ่ม **ข้อมูลติดต่อ** ตามด้วยความคืบหน้าที่ผู้ใช้บันทึก ส่วนสรุปตามหมวด เงื่อนไข เอกสาร และแหล่งข้อมูลพร้อมวันที่ตรวจล่าสุด แยกสถานะของประกาศออกจากสถานะที่ผู้ใช้แจ้ง ตัวอย่างเช่น ทุนอาจปิดรับแล้วขณะที่แผนยังเป็น **กำลังทำ**

หน้า **ข้อมูลติดต่อ** ใช้ชื่อและหมวดเดิม แสดงช่องทางตามวัตถุประสงค์ เช่น **ยื่นเรื่อง**, **สมัครงาน**, **ถามก่อนเดินทาง**, หรือ **ติดตามผล** แต่ละช่องทางระบุหน่วยงานและสิ่งที่ควรทำ วางเอกสารที่ใช้ก่อนติดต่อและข้อมูลพื้นที่ไว้คนละส่วน แสดงปุ่มโทร เปิดเว็บไซต์ ส่งอีเมล หรือเปิดแผนที่เฉพาะช่องทางที่มีปลายทางครบและตรวจสอบได้ ข้อมูลเดิมที่มีเพียงชื่อสำนักงานหรือข้อความแนะนำยังแสดงให้อ่านได้

| รูปแบบ | หมวด | ข้อมูลหลักที่ผู้ใช้ต้องเห็น |
| --- | --- | --- |
| สิทธิ์และเงิน | **1 สวัสดิการรัฐ** | ผลประเมินพร้อมที่มา เกณฑ์สำคัญ ยอดและรอบจ่าย เขตทะเบียนบ้านหรือเขตที่ให้บริการ หน่วยงานรับคำขอ |
| สิทธิ์และเงิน | **2 เงินคืน** | ประเภทเงินคืน คู่กรณีหรือหน่วยงาน ปีภาษีหรือช่วงอ้างอิง หลักฐานการจ่าย ช่องทางยื่นและติดตาม ยอดคืนเมื่อมีหลักฐาน |
| สิทธิ์และเงิน | **3 เงินค้างจ่าย** | ผู้ค้างจ่าย ช่วงที่ค้าง วิธีคำนวณจากข้อมูลที่มี หลักฐานการทำงานหรือการทวง ช่องทางร้องเรียนและกรอบเวลาถ้ามีต้นทาง |
| งาน | **4 งานประจำ** | ตำแหน่ง นายจ้าง สถานที่หรือรูปแบบทำงาน เงินเดือน สวัสดิการ เวลางาน และลิงก์ประกาศ |
| งาน | **5 พาร์ตไทม์** | กะ วันทำงาน ค่าตอบแทนต่อชั่วโมงหรือต่อวัน จุดนัดหรือสถานที่ทำงาน และวิธีจองกะหรือสมัคร |
| งาน | **6 ฟรีแลนซ์** | ขอบเขตและสิ่งที่ส่งมอบ ค่าตอบแทนต่องาน กำหนดส่ง งวดจ่าย และช่องทางติดต่อผู้ว่าจ้าง |
| ช่องทางหารายได้ | **7 ขายสินค้า** | ประเภทสินค้าที่รับ จุดขายหรือรับซื้อ ราคา ค่าธรรมเนียม เงื่อนไขรับสินค้า และเวลานัด |
| ช่องทางหารายได้ | **8 ใช้ทรัพย์สิน** | ประเภททรัพย์สิน รูปแบบการให้เช่าหรือหารายได้ ต้นทุน ค่ามัดจำ เงื่อนไขส่งมอบและคืน |
| ทุน | **9 ทุนให้เปล่า** | ผู้ให้ทุน วงเงิน รอบเปิดรับ วันปิดรับและเวลา คุณสมบัติ เอกสาร ประกาศผล และช่องทางสมัคร |
| ช่องทางหารายได้ | **10 ทักษะ** | แยก `training` กับ `paid_service` โดยใช้โครงเดียวกัน อบรมแสดงทักษะที่จะได้ รอบเรียน เวลา สถานที่ และค่าเรียน ส่วนงานจากทักษะแสดงงานที่รับ ค่าตอบแทนและสมมติฐาน |

## การรับข้อมูลผ่าน API

ใช้ `taskId` อ่านข้อมูลความคืบหน้าจาก `GET /v1/tasks/{id}` ใช้ `moneyId` หรือ `opportunityId` บนแผนไปอ่านรายการต้นทางจาก API เดิม หน้า Info กับหน้าติดต่อใช้ข้อมูลรายการชุดเดียวกันในหนึ่งรอบเปิดหน้า และผูกบริบทพื้นที่ด้วย `districtCode` เมื่อระบบมีค่าอยู่แล้ว รองรับหมวดด้วย `category` และจุดผูกจากรหัสระบบเดิมตามตาราง ไม่ใช้ `mapGroup` ตัดสินแบบหน้าเพียงอย่างเดียว

| เจ้าของข้อมูล | พารามิเตอร์ที่ UI ใช้ |
| --- | --- |
| แผนผู้ใช้ | `taskId`, `opportunityId` หรือ `moneyId`, `title` สำหรับ fallback, `steps`, `doneCount`, `status`, `dueText?`, `outcome?` และ `districtCode?` ความคืบหน้าเป็นการแจ้งของผู้ใช้ |
| รายการต้นทาง | `category`, `title`, `organization?`, `summary?`, `description?`, `conditions[]?`, `documents[]?`, `amount?` พร้อมหน่วยและที่มาของตัวเลข, `availability?`, `sourceUrl?`, `checkedAt?`, `expiresAt?` และ `dataStatus` |
| ข้อมูลเฉพาะหมวด | เปิดใช้ตามชนิดของรายการ เช่น `claim` สำหรับรอบจ่ายหรือหลักฐาน, `job` สำหรับกะ หรือสิ่งที่ต้องส่งมอบ, `income` สำหรับต้นทุนหรือค่าธรรมเนียม, `grant` สำหรับรอบและวันปิดรับ ผูกป้ายภาษาไทยใน UI และรับค่าข้อมูลจาก API |
| พื้นที่และช่องทาง | `locations[]?` ระบุเขต ที่อยู่ พิกัดและความแม่นยำเมื่อมี ส่วน `contacts[]?` ระบุ `purpose`, `type`, `label`, `destination?`, `hoursText?`, `instructions?`, `districtCode?`, `sourceUrl?` และ `checkedAt?` ปรับจาก `MoneyRoute.channels` หรือ `Opportunity.provenance` ที่มีอยู่ได้ |

ก่อนต่อ DB ควรเติมข้อมูลติดต่อแบบมีชนิดและวัตถุประสงค์เป็นอันดับแรก ช่อง `sourceUrl` เดิมช่วยเปิดต้นทางได้ แต่ยังบอกไม่ได้ว่าลิงก์นั้นใช้สมัคร ติดตาม หรืออ่านประกาศ ต่อมาควรเติมกำหนดปิดรับแบบมีเขตเวลา สถานะเปิดรับ วันที่ตรวจล่าสุด และข้อมูลเฉพาะหมวดตามตาราง ส่งวันที่แบบมีเขตเวลาแล้วแสดงเป็นเวลาประเทศไทย ระบุหน่วยและที่มาของตัวเลขเพื่อให้แยกค่าตอบแทนจริง ช่วงประมาณ และยอดที่รอตรวจได้

- ค่าไม่ทราบให้ซ่อนแถวรอง แสดง **ยังไม่มีช่องทางติดต่อที่ตรวจสอบได้** เมื่อผู้ใช้เปิดหน้าติดต่อแล้วยังไม่มีข้อมูลที่ใช้ได้ ช่องทางที่เป็นข้อความไม่มีปุ่มเปิดปลายทาง
- หากรายการหมดอายุ แสดงวันปิดรับตามต้นทาง ปิดการสมัครหรือยื่นรอบเดิม และคงข้อมูลอ้างอิงกับความคืบหน้าในแผน หากอ่านต้นทางไม่ได้ ให้ใช้ชื่อและข้อมูลแผนที่ยังมี แสดงปุ่มลองใหม่เมื่อเป็นข้อผิดพลาดชั่วคราว
- ใช้ข้อความกำกับหมวดและสถานะร่วมกับสี ให้คีย์บอร์ดและโปรแกรมอ่านหน้าจอเข้าถึงรายการ ปุ่มย้อนกลับ และลิงก์ได้ ใช้หัวข้อแยกส่วน ลำดับโฟกัสตามหน้าจอ และคืนโฟกัสไปยังปุ่มที่เปิดหน้า ข้อความและปุ่มต้องอ่านได้บนจอเล็กเมื่อขยายตัวอักษร
- หากฐานหรือ API ส่วนขยายยังไม่มี ให้ใช้ข้อมูลชุดเดิมและ fixture สำหรับ Demo ข้อมูลตัวอย่างต้องมีป้ายและต้องไม่มีปลายทางที่สมมติขึ้นมาใช้งานจริง

## เกณฑ์ตรวจรับข้อ 7

| รหัส | สิ่งที่ต้องตรวจ |
| --- | --- |
| AC-10 | เปิดรายการจาก **แผนของฉัน** แล้วเห็นชื่อ หมวด ข้อมูลสำคัญ ความคืบหน้าและส่วนเฉพาะ ถูกต้องครบสิบหมวด ใช้รูปแบบสรุปสี่แบบ |
| AC-11 | กด **ข้อมูลติดต่อ** แล้วเห็นชื่อรายการเดิม เอกสาร ช่องทาง และพื้นที่เท่าที่มี ไม่มีการเปิดปลายทางอัตโนมัติ กลับมาแล้วความคืบหน้าและโฟกัสอยู่ที่เดิม |
| AC-12 | ทดลองประกาศหมดอายุ รายการไม่มีช่องทาง และ API อ่านต้นทางไม่ได้ สถานะต่างกันและยังกลับไปที่แผนเดิมได้ |
| AC-13 | ใช้คีย์บอร์ดและจอมือถือเปิดทั้งสองหน้า อ่านหัวข้อและสถานะได้โดยไม่อาศัยสี ปุ่มที่ต้องใช้ยังมองเห็นและกดได้ |
| AC-14 | เปิดแท็บที่มีรายการและแท็บว่างใน Flutter เทียบกับภาพอ้างอิง Header และลำดับการ์ดตรงแบบ ตัวนับแสดงเฉพาะเมื่อมีรายการ และปุ่มหน้าว่างเปิดหน้าแรกได้ |
| AC-15 | ลองแผน active, blocked, snoozed และ finished มีหลายกลุ่มแล้วแสดงหัวข้อกลุ่มตามลำดับ แสดงป้ายสถานะที่ต่างกัน ขั้นถัดไปและเศษส่วนตรงกับข้อมูล และขั้นถัดไปหายเมื่อจบแผน |
| AC-16 | เปิดแผนเก่าที่ไม่ส่งหมวด แผนโอกาสที่ทราบหมวด และแผน Demo ทุกการ์ดอ่านและเปิดได้ แสดงหมวดเมื่อรู้ค่า ป้าย Demo เดิมยังอยู่ และกดย้อนกลับแล้วเห็นความคืบหน้าล่าสุด |
| AC-17 | ตรวจบน Android จอแคบและเมื่อขยายตัวอักษร หมวด สถานะ ชื่อ และความคืบหน้าอ่านได้ ทดสอบดึงเพื่อรีเฟรช ลองใหม่เมื่อโหลดไม่สำเร็จ และเปิดรายละเอียดจากการ์ดด้วย TalkBack หรือการทดสอบ semantics |
