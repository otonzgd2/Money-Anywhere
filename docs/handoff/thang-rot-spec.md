# สเปกแอปทางรอด

สำหรับ `otonzgd2/Money-Anywhere` ฝั่ง Flutter Android ส่งมอบข้อ 0–7 เป็นการเปลี่ยนแปลงชุดเดียว ตั้งแต่เปิดแอปจนเห็นรายการใน **แผนของฉัน**

เปิดแอป → โลโก้ทางรอด → เลือกเชื่อมข้อมูลจำลองครั้งแรก → ประเมินสิทธิ์ สวัสดิการ และรายได้อัตโนมัติ → **โอกาส** → **รายละเอียด** → **บันทึกแล้ว**

[ไฟล์อ้างอิงหน้าโอกาสและหน้า Info](../mockups/bangkok-opportunity-scope.html) กำหนดรหัสหมวด 1–10 บริบทเขต และข้อมูลที่หน้า Info ต้องรับ เป้าหมาย 50 เขตและ 5,100 รายการเป็นขอบเขตของงานจัดทำข้อมูล งานนี้ใช้ API และฐานข้อมูลที่มีอยู่ หากยังไม่มีฐานของรายการหรือพิกัด ให้ใช้สถานะว่างและเตรียม UI รับข้อมูลจาก API โดยไม่สร้างฐาน ตาราง หรือชุดนำเข้าใหม่

## 0–1 ชื่อและหน้าขณะเปิดแอป

- ชื่อที่ผู้ใช้เห็นบน Android launcher และในตัวแอปคือ **ทางรอด** ใช้ application ID เดิมเพื่อให้การอัปเดตบนเครื่องรักษาข้อมูลและแผนที่มีอยู่
- เมื่อเปิดแอปจากสถานะปิด ให้แสดงโลโก้ทางรอดจากไฟล์ที่แนบ โดยจัดกลางจอและรักษาสัดส่วน ใช้ภาพเดียวกันตั้งแต่ Android launch screen ถึงหน้ารอของ Flutter เพื่อเลี่ยงการเห็นโลโก้เดิมหรือหน้ารอที่มีแต่ spinner
- เปลี่ยนไปหน้าถัดไปเมื่อพร้อม โดยไม่กำหนดเวลาหน่วงขั้นต่ำ หากเริ่มแอปไม่ได้ ให้มีทางลองใหม่จากหน้ารอ

## 2 Modal เชื่อมข้อมูลจำลองครั้งแรก

ในโหมด Demo ให้เปิด modal หลังหน้าขณะเปิดแอป เรียงทีละบริการตามตาราง ปุ่ม **เชื่อมต่อข้อมูลจำลอง** เลือกใช้เฉพาะชุดข้อมูลของขั้นนั้นในรอบนี้ ปุ่ม **ข้าม** ไปขั้นถัดไป และ **ข้ามทั้งหมด** ข้ามทุกขั้นที่เหลือโดยคงแหล่งที่เลือกไปแล้ว ทั้งสี่แหล่งเลือกหรือข้ามได้อย่างอิสระ

| ลำดับ | บริการและภาพ | ข้อมูลตัวอย่างที่ระบุใน modal | ค่าใน API เดิม |
| --- | --- | --- | --- |
| 1 | <img src="thang-rot-assets/thaid.png" width="48" alt="ไอคอน ThaID"> ThaID | อายุหรือช่วงอายุ และเขตตามทะเบียนบ้านจำลอง | `thaid` |
| 2 | <img src="thang-rot-assets/thangrat.png" width="48" alt="ไอคอนทางรัฐ"> ทางรัฐ | สถานะบัตรประจำตัวคนพิการจำลอง | `tangRat` |
| 3 | <img src="thang-rot-assets/sso-plus.png" width="48" alt="ไอคอน SSO+"> ประกันสังคม (SSO+) | มาตราผู้ประกันตนและประวัติส่งเงินสมทบจำลอง | `socialSecurity` |
| 4 | <img src="thang-rot-assets/d-mytax.png" width="112" alt="โลโก้ D-MyTax"> D-MyTax | ปีภาษีและยอดหักภาษี ณ ที่จ่ายจำลอง | `dMyTax` |

ใช้ไฟล์ภาพแบบ bundled asset จัดให้ภาพ D-MyTax แสดงครบตามสัดส่วน ป้าย **DEMO / MOCK** และข้อความ **ใช้ข้อมูลจำลองเพื่อประเมินสิทธิ์และรายได้** ต้องเห็นก่อนกดปุ่ม เชื่อมต่อในแอปด้วยข้อมูลสังเคราะห์เท่านั้น การเลือกนี้ให้สิทธิ์ใช้ข้อมูลจำลองในขั้นประเมิน สิทธิ์บันทึกข้อมูลส่วนบุคคลหรือบันทึกแผนใช้ขั้นตอนเดิมของแอป

ค่าที่แนะนำสำหรับการใช้งานจริงใน Demo มีดังนี้

- บันทึกสถานะรายแหล่ง **ยังไม่เลือก**, **เลือกข้อมูลจำลอง**, หรือ **ข้าม** ในที่เก็บภายในแอปและผูกกับเวอร์ชัน onboarding โดยเก็บเฉพาะการเลือกและความคืบหน้าของ modal ถ้าปิดแอปกลางทาง ให้กลับมาขั้นแรกที่ยังไม่เลือก เมื่อจบแล้วเปิดครั้งต่อไปที่ **โอกาส** โดยไม่เปิด modal ซ้ำ
- เริ่มประเมินอัตโนมัติหลังตัดสินใจครบสี่แหล่งหรือกดข้ามทั้งหมด ใน `APP_MODE=user` เปิด **โอกาส** ตามเส้นทางปกติและใช้เฉพาะข้อมูลที่ผู้ใช้มีอยู่
- ใช้ `GET /v1/app-config` ตรวจว่า Demo พร้อมใช้งาน หากโหลดไม่ได้ ให้ผู้ใช้เข้าหน้า **โอกาส** และลองโหลดใหม่ได้ สถานะที่ตรวจไม่ได้ยังไม่ถือว่าผู้ใช้จบ onboarding

แหล่งภาพที่ใช้ใน Demo คือ [ThaID โดยกรมการปกครอง](https://play.google.com/store/apps/details?id=th.go.dopa.bora.dims.ddopa), [ทางรัฐโดย สพร.](https://play.google.com/store/apps/details?id=th.or.dga.citizenportal), [SSO+ โดยสำนักงานประกันสังคม](https://play.google.com/store/apps/details?id=com.sso.ssoplus) และ [ตรา D-MyTax จากหน้าบริการกรมสรรพากร](https://www.rd.go.th/272.html) ตามโลโก้ของบริการภาษีบนเว็บ [ไฟล์ภาพ D-MyTax จากกรมสรรพากร](https://www.rd.go.th/fileadmin/2020pages/272/services/icon-dmytax-newV2.png)

## 3 คำนวณอัตโนมัติก่อนเข้าโอกาส

แสดงสถานะ **กำลังประเมินสิทธิ์และรายได้** ระหว่างคำนวณ เมื่อได้ผลให้เปิดแท็บ **ทั้งหมด** ของหน้า **โอกาส** พร้อมสรุปผล การข้ามทุกบริการหรือมีข้อมูลไม่ครบยังเข้าหน้าโอกาสได้ หากการประเมินล้มเหลว ให้เปิดหน้าโอกาสพร้อมสถานะ **ยังประเมินไม่สำเร็จ** และปุ่ม **ลองใหม่** โดยผู้ใช้ยังดูรายการได้

| ผล | ข้อมูลและวิธีแสดง |
| --- | --- |
| สิทธิ์และสวัสดิการ | ใช้ผลจากตัวประเมินเดิม `POST /v1/money/preview` เมื่อประเมินจากข้อมูลจำลอง เมื่อไม่ใช้ข้อมูลจำลองให้อ่านผลจากข้อมูลเดิมของเครื่องผ่าน `GET /v1/money` ได้ หากไม่มีข้อมูลให้แสดง **ข้อมูลยังไม่พอประเมิน** แยกยอดรายเดือน ยอดครั้งเดียว และรายการที่ต้องตรวจต่อ ใช้สถานะต่อรายการของ API และแสดงที่มาของจำนวนเงิน |
| เงินคืนและเงินค้างจ่าย | จัด `tax_refund` ไว้หมวด 2 และ `unpaid_wages` ไว้หมวด 3 ส่วน `old_age`, `unemployment`, `child_support` และ `disability` อยู่หมวด 1 ภาษีที่ถูกหักไม่ใช่ยอดเงินคืน หากกฎยังให้ยอดไม่ได้ให้แสดง **ตรวจสอบยอดกับหน่วยงาน** |
| รายได้ | แสดงช่วงค่าตอบแทนต่อรายการและหน่วยจากประกาศ หรือช่วงรายได้สุทธิต่อเดือนที่มีที่มาจากแผนเดิม `GET /v1/plans/options` พร้อมสมมติฐานที่ API ส่งมา เมื่อไม่มีตัวเลขให้แสดง **ยังไม่มีข้อมูลรายได้** ใช้ยอด **ตามประกาศ** หรือ **ประมาณการ** ตามแหล่งข้อมูล และแยกจากยอดสวัสดิการ |

ใช้ชุด `gov-prefill` และกฎเดิมเป็นหลัก เมื่อต้องอ่าน `facts` จาก `POST /v1/demo/personas/gov-prefill?sources=…` ให้เรียกด้วย device ID สำหรับ Demo เฉพาะ onboarding เพราะปลายทางนี้แทนที่ข้อมูลของ device ที่ส่งมา ส่ง `facts` ของแหล่งที่เลือกและคำตอบพื้นฐานของ persona ซึ่งเป็นข้อมูลสมมติทั้งหมดเข้า preview จัดเก็บคำตอบจริงไว้ในโปรไฟล์หลักตามเดิม ถ้าไม่มีแหล่งที่เลือก ให้ข้ามการโหลด persona เพื่อไม่ดึงคำตอบพื้นฐานสมมติมาประเมินให้ผู้ใช้ ผลที่อาศัยข้อมูลจำลองต้องติด **DEMO / MOCK** แม้ `/v1/money/preview` ส่งสถานะ `curated` สำหรับกฎที่ใช้ หน้าโอกาสแสดงสถานะแนวโน้มและยอดที่มีหลักฐานโดยไม่ยืนยันว่าผู้ใช้จะได้รับเงินหรืองาน

เส้นทางนี้เริ่มและแสดงผลในแอปทันทีโดยใช้ API ประเมินที่มีอยู่ ไม่มีหน้าคำนวณสำหรับผู้ดูแล การใช้แอปต่อ การข้ามทั้งหมด และการลองใหม่ไม่ต้องเปิดแชตหรือกรอกฟอร์มก่อน

## 4 หน้าโอกาสและแผนที่

| แถบ | ชื่อบนจอ | หมวดจาก HTML และค่าจาก API เดิม |
| --- | --- | --- |
| 0 | ทั้งหมด | 1–10 รวมผลประเมินและรายการโอกาสที่ตรงตัวกรอง |
| 1 | สิทธิ์และสวัสดิการ | 1 สวัสดิการรัฐ `welfare`, 2 เงินคืน `refund`, 3 เงินค้างจ่าย `owed` |
| 2 | หางาน | 4 งานประจำ `job_full`, 5 พาร์ตไทม์ `job_part`, 6 ฟรีแลนซ์ `freelance` |
| 3 | ขายสินค้า | 7 ขายสินค้า `sell` |
| 4 | อื่นๆ | 8 ใช้ทรัพย์สิน `assets`, 9 ทุนให้เปล่า `grant`, 10 ทักษะ `skill` |

- แถบ **สิทธิ์และสวัสดิการ** จัดผลตามหมวด 1–3 และแถบ **อื่นๆ** จัดรายการตามหมวด 8–10 ใช้รหัสหมวดในการจัดกลุ่ม เพราะ `mapGroup: money` เดิมครอบคลุมทั้งสิทธิ์ ทรัพย์สิน และทุน
- แถบ **หางาน** ใช้ dropdown **ประเภทงาน** ที่มี checkbox สำหรับทั้งสามหมวด เลือกหลายประเภทได้ ผลเป็นการรวมประเภทที่เลือก การไม่เลือก checkbox ใดหมายถึงทุกประเภท กรองด้วยประเภทการจ้าง `category` ส่วน `workMode` เดิมคือ onsite, hybrid หรือ remote
- รับคำค้นและบริบทเขตตามไฟล์ HTML ค่าเริ่มต้นคือ **ทุกเขตในกรุงเทพฯ** ใช้เฉพาะเขตที่แหล่งข้อมูลระบุหรือยืนยันว่ารายการให้บริการได้ เมื่อเปิดรายละเอียดแล้วกลับ ให้คงแถบ เขต คำค้น ตัวกรอง และมุมมองเดิม
- ผูกข้อมูลกับ `GET /v1/opportunities` และอ่านหน้าถัดไปตาม `nextCursor` สำหรับการเลือกหลายหมวด API เดิมรับ `category` ทีละค่า ให้รวมผลจากคิวรีต่อหมวดและตัดรายการซ้ำด้วยรหัส ห้ามกรองเฉพาะหน้าแรกของผลทั้งหมด ใช้ SQLite งานเดิมหาก API ตั้งค่าให้ส่งข้อมูลจากฐานนั้น
- ให้ list และแผนที่ใช้เขตและตัวกรองชุดเดียวกัน ใช้ `OppMap` เดิมเมื่อมีรายการจากฐานข้อมูลพร้อมพิกัดยืนยันได้ `precision=exact` และ latitude/longitude ที่อยู่ในช่วงถูกต้อง แสดงหมุดด้วยคู่ `opportunityId + districtCode` ที่ตรงบริบท กดหมุดเปิดรายละเอียดเดียวกับการกดการ์ด รายการที่มีเพียงเขต พื้นที่ให้บริการ หรือทำงานทางไกลยังอยู่ใน list แต่ไม่มีหมุดสมมติ
- ถ้าแหล่งข้อมูลแผนที่ยังไม่พร้อมหรือไม่มีพิกัดตรงตัวกรอง ให้คงหน้า list และแสดง **ยังไม่มีพิกัดสำหรับตัวกรองนี้** เมื่อผู้ใช้เลือกดูแผนที่ UI รองรับพิกัดที่ส่งจาก API โดยตรง ต้นทางของพิกัดต้องมาจาก adapter ที่รู้ว่าข้อมูลมาจากฐาน เพื่อให้แยกจาก fixture ได้

## 5–6 หน้ารายละเอียดและการบันทึก

ใช้หน้า **รายละเอียด** รูปแบบเดียวกันทุกหมวด มีป้ายและสีหมวด กล่องสรุป ชื่อ ผู้เผยแพร่ ข้อมูลค่าตอบแทนหรือสิทธิ์ รายละเอียด เงื่อนไข ช่องทางติดต่อ ลิงก์ต้นทาง แหล่งข้อมูลและวันที่ตรวจล่าสุด ส่วนที่อยู่ การเดินทาง พิกัด และวันหมดอายุปรากฏเมื่อมีข้อมูลจากต้นทาง

เปิดด้วยรหัสรายการและบริบทเขต แล้วอ่านรายละเอียดล่าสุดจาก `GET /v1/opportunities/{id}` แม้มีข้อมูลสรุปบนการ์ดแล้ว ใช้ endpoint เดิมของรายการเงินสำหรับผลคำนวณตาม `moneyId` และใช้ผล preview ประกอบในหน้าเดียวกันโดยไม่เขียนข้อมูลสังเคราะห์ลงโปรไฟล์จริง ถ้าข้อมูลยังโหลดได้เพียงบางส่วน ให้แสดงข้อมูลที่ทราบตามแหล่ง หากรหัสไม่พบหรือรายการหมดอายุ ให้แสดง **ไม่พบรายการนี้หรือรายการหมดอายุแล้ว** และทางกลับไปหน้าโอกาส ถ้าเป็นความผิดพลาดชั่วคราว ให้ลองโหลดใหม่ได้ การเปิดหน้าด้วยรหัสโดยตรงต้องได้รายการเดิมแม้ไม่ได้ผ่าน list

- งานใช้ข้อความปุ่ม **รายละเอียดงาน** เชื่อมไปที่หน้ารายละเอียดของประกาศต้นทางตามพฤติกรรมเปิดลิงก์เดิม ถ้าต้นทางใช้ไม่ได้ให้แสดงสถานะในหน้า ใช้หน้าตัวอย่างเดิมได้เฉพาะ Demo ที่ติดป้ายชัดเจน
- ปุ่ม **บันทึกไว้ในแผนของฉัน** ใช้ `saveToPlan` และ `POST /v1/tasks` ตามรหัส `opportunityId` หรือ `moneyId` กดซ้ำระหว่างรอไม่ได้ เปลี่ยนเป็น **บันทึกแล้ว** หลัง API สำเร็จหรือเมื่อพบแผนเดิมของรหัสนี้ใน `GET /v1/tasks` ยกเลิกความยินยอมหรือบันทึกล้มเหลวให้คงข้อความเดิมและลองใหม่ได้
- เมื่อกลับมาเปิดรายละเอียดใหม่ ให้แสดงตามสถานะที่บันทึกจริง หากผู้ใช้ลบแผน ปุ่มกลับเป็น **บันทึกไว้ในแผนของฉัน** รายการเดียวกันที่เข้าจากคนละเขตใช้แผนเดียวกัน

### ข้อมูลที่ UI รับจาก API

ชื่อฟิลด์ด้านล่างเป็นรูปแบบที่ UI ใช้ภายใน ให้ adapter แปลงจาก `Opportunity`, `Location`, `Provenance` และผลประเมินเดิมได้ โดยไม่บังคับให้ฐานข้อมูลใช้ชื่อเดียวกัน

| ส่วน | ฟิลด์และความหมาย |
| --- | --- |
| การค้นหา | `categoryIds[]` รหัส 1–10, `districtCode?`, `q?`, `cursor?` รับ `items[]` และ `nextCursor?` เมื่อ API เดิมส่งชื่อเขตให้ map เข้าบริบทที่รู้จัก หากไม่ทราบให้คงชื่อโดยไม่สร้างรหัสเอง |
| ระบุตัวรายการ | `kind` เป็น opportunity หรือ money และมีรหัสที่เสถียรของชนิดนั้น `districtCode?` ใน route เป็นตัวเลือกรายละเอียดพื้นที่ รหัสเดียวกันที่ใช้หลายเขตไม่กลายเป็นหลายรายการหลัก |
| สรุปและรายละเอียด | `categoryId`, `title`, `organization?`, `description?`, `conditions[]?`, `contacts[]?`, `sourceUrl?`, `dataStatus`, `status?`, `checkedAt?`, `expiresAt?` และข้อมูลเงิน `min?`, `max?`, `unit?`, `basis?` |
| พื้นที่ | `locations[]?` รองรับหลายเขตต่อรายการ โดยแต่ละพื้นที่มี `districtCode?`, `districtName?`, `areaType?`, `address?`, `travelInfo?`, `lat?`, `lng?`, `precision?` และหลักฐานที่มาของพิกัด รับ `location` แบบรายการเดียวของ API เดิมได้ |

## 7 แผนของฉัน รายละเอียดและข้อมูลติดต่อ

เปิดรายการจาก **แผนของฉัน** แล้วใช้หน้า Info โครงร่วมและข้อมูลสรุป 4 แบบสำหรับสิบหมวด นำ UI รายการจาก DEMO ล่าสุดเข้า Flutter ด้วย header ชื่อหน้าและจำนวนแผน การ์ดที่เห็นสถานะ ขั้นถัดไปและความคืบหน้า และกลุ่มตามสถานะ ดู AC-10–AC-17 ใน [สเปกข้อ 7 และ DEMO](thang-rot-plan-info-spec.md)

## โปรไฟล์และบัญชีที่เชื่อมต่อ

[เปิด DEMO](../mockups/index.html) กด **ลองเปิดแอปครั้งแรก** เลือกบริการที่ต้องการ จากนั้นเปิดแท็บ **ฉัน**

ใช้การ์ด **ข้อมูลส่วนตัว** และ **งานและรายได้** ในหน้าโปรไฟล์ ปุ่ม **บันทึกโปรไฟล์** อยู่ด้านล่างและเข้าถึงได้ขณะใช้แป้นพิมพ์หรือขยายตัวอักษร ส่วน **บัญชีที่เชื่อมต่อ** อยู่ในแท็บ **ฉัน** ใช้โลโก้จาก onboarding พร้อมข้อความสถานะ กางรายละเอียดแยกตามบริการ ดู [โปรไฟล์เมื่อเชื่อม ThaID](thang-rot-assets/profile-thaid-reference.png), [โปรไฟล์ที่กรอกเอง](thang-rot-assets/profile-manual-reference.png) และ [บัญชีที่เชื่อมต่อ](thang-rot-assets/connected-accounts-reference.png)

- **ฉัน → โปรไฟล์** แสดงชื่อ อายุ และเขตตามทะเบียนบ้านที่ ThaID ส่งมาในส่วนข้อมูลส่วนตัว พร้อมป้ายกำกับที่มาและสถานะอ่านอย่างเดียว หาก ThaID ส่งมาเพียงบางช่อง ให้แสดงค่าที่ได้รับและระบุว่าช่องใดไม่มีข้อมูล ช่องที่มาจาก ThaID ต้องอ่านอย่างเดียวที่ API ด้วย
- เมื่อยังไม่เชื่อม ThaID ให้แก้ไขและบันทึกชื่อที่ใช้ในแอป ช่วงอายุ และเขตที่อาศัยได้ ทักษะ เวลาว่าง และเป้ารายได้อยู่ในส่วน **งานและรายได้** และแก้ไขได้ในทั้งสองสถานะ การเชื่อม ThaID ใช้ข้อมูลจากต้นทางในการแสดงผลโดยเก็บค่าที่ผู้ใช้กรอกไว้ก่อนหน้า เมื่อยกเลิกเชื่อมให้กลับไปใช้ข้อมูลที่ผู้ใช้กรอกเอง
- **ฉัน → บัญชีที่เชื่อมต่อ** เรียง ThaID, ทางรัฐ, ประกันสังคม (SSO+) และ D-MyTax ตามลำดับ onboarding แสดงจำนวนที่เชื่อมแล้วและสถานะแต่ละบริการ กางดูข้อมูลได้เฉพาะบริการที่เชื่อมสำเร็จ เช่น ข้อมูลตัวตน สถานะบัตรประจำตัวคนพิการ ประวัติสมทบ และข้อมูลภาษีหัก ณ ที่จ่ายตามลำดับ แสดง **ยังไม่เชื่อม · ข้ามตอนเริ่มต้น** สำหรับแหล่งที่ข้ามโดยไม่มีค่าจากแหล่งนั้น
- ใช้สถานะที่บันทึกจากการเลือกครั้งแรกประกอบผลโหลดจริงของแต่ละบริการ หากผู้ใช้เลือกเชื่อมแล้วแต่โหลดไม่สำเร็จ ให้แสดงสถานะโหลดไม่ได้และทางลองใหม่ แหล่งที่ใช้ข้อมูลสังเคราะห์มีป้ายกำกับ **DEMO / MOCK** เก็บและแสดงเฉพาะค่าที่จำเป็นต่อการใช้งาน

ชื่อและเขตจาก ThaID เป็นข้อมูลจากทะเบียน ส่วนเขตที่ผู้ใช้กรอกเองเป็นเขตที่อาศัยและต้องคงการใช้งานเดิมกับโอกาสงาน หากข้อมูลจาก ThaID มีเพียงบางช่อง ให้แสดงเฉพาะค่าที่ได้รับ ช่องที่หายแสดง **ไม่มีข้อมูลจาก ThaID** ใช้อายุหรือช่วงอายุที่ระบบได้รับตามสิทธิ์ เปิดให้แก้ทักษะ เวลาว่าง และเป้ารายได้ได้ตามเดิม

ตัวเลือก **ข้ามตอนเริ่มต้น** ใช้เมื่อมีคำตอบว่าข้ามเท่านั้น หากเป็นการติดตั้งที่ไม่มีบันทึก onboarding ให้แสดง **ยังไม่เชื่อม** ใน DEMO การลองใหม่โหลดข้อมูลของบริการที่เลือกซ้ำได้ โหมดผู้ใช้แสดงผลตามหลักฐานการเชื่อมต่อที่ระบบมีอยู่ สำหรับบริการที่ยังไม่มีตัวเชื่อมจริงให้แสดง **ยังไม่เชื่อม**

ใช้ [Handoff สำหรับ Flutter](thang-rot-dev-handoff.md#นำ-ui-โปรไฟล์และบัญชีที่เชื่อมต่อจาก-demo-เข้า-flutter) เพื่อดูเส้นทางข้อมูลและจุดแก้ในโค้ด
