# สเปกทางรอดสำหรับคัดกรองและเข้าใจเจตนาก่อน LLM

Phase นี้รองรับการเช็กเงินที่ผู้ใช้แอปอาจมีสิทธิรับและการวางแผนหาเงินเพิ่มให้ตัวเอง ใช้ข้อมูลจาก ThaID, ทางรัฐ, ประกันสังคม และ D-MyTax ร่วมกับคำตอบในโปรไฟล์ ผู้ใช้เริ่มได้แม้ยังไม่ได้เชื่อมบริการ

## ปัญหาที่ต้องแก้

ใน mock server ของ checkout นี้ “อยากได้ตัง 5000 หาให้หน่อยดิ๊” เข้า `plan_income_goal` แล้วกลายเป็นเป้า 5,000 บาทต่อเดือนทันที ส่วน “มีอะไรให้ทำจากบ้านบ้าง เดินไกลไม่ไหว” ได้ข้อความจำกัดขอบเขตและถูกพากลับไปถามอายุ การแก้ทั้งสองกรณีต้องรู้ว่าผู้ใช้กำลังขออะไร และรู้ด้วยว่าข้อมูลอะไรที่ผู้ใช้ยังไม่ได้ระบุ. [ผลทดสอบและ test cases](thang-rot-guard-test-spec.md)

`goalTarget()` คืนเฉพาะตัวเลข ตัววางแผนเดิมรับเป้าต่อเดือน และแชทแบบ `guided` สร้างคำถามแรกจากรายการเงินทันที บางข้อความที่ไม่ตรงคำศัพท์ของ guard ถูกส่งเข้า `ai.extract()` เพื่อเดาคำตอบของข้อที่ค้าง ระบบจึงอาจพลาดทั้งเจตนาใหม่และความหมายของคำตอบสั้นที่อิงคำถามก่อนหน้า. [ตัวอ่านเป้ารายได้](../../contracts/adapters/agent.js#L50) · [เส้นทางข้อความในแชท](../../contracts/mock-server.js#L607)

## แนวทางเลือกเจตนาและคำถาม

| วิธี | พฤติกรรม | ผลต่อ Phase นี้ |
| --- | --- | --- |
| เพิ่มคำในรายการเดิม | จับ “ตัง”, “ทำจากบ้าน” และคำใกล้เคียงเพิ่ม | รองรับประโยคที่รู้ล่วงหน้า ส่วนคำตอบสั้น ข้อความที่มีหลายยอด และการเปลี่ยนเรื่องยังต้องเพิ่มกฎเฉพาะ |
| ให้ LLM ตีความทุกข้อความหลังตรวจข้อมูลลับ | ส่งข้อความและบริบทเพื่อให้โมเดลเลือกหัวข้อทุกครั้ง | เพิ่มการเรียกโมเดลแม้ผู้ใช้กดปุ่มหรือมีข้อมูลครบแล้ว และต้องมีทางเดินเมื่อโมเดลใช้ไม่ได้ |
| **ใช้กฎและบริบทใน guard แล้วส่งคำขอที่ผ่านการคัดกรองให้ LLM** | แอปแยกเจตนา คำตอบ และข้อมูลที่ยังขาดด้วยกฎ ถ้าเจตนาคลุมเครือให้ถามสั้น ๆ แล้วให้ LLM ช่วยอธิบายหรือวางทางเลือกเมื่อได้บริบทพอ | ใช้เป็นแนวทางของ Phase นี้ ตัวอย่างหลักและทางเดินด้วยปุ่มต้องทำงานแม้ปิด LLM |

1. ตรวจข้อมูลลับที่ผู้ใช้ส่งจริงและคำสั่งที่พยายามเปลี่ยนกฎของผู้ช่วยก่อนเข้าประวัติหรือเรียกโมเดล คำถามอย่าง “สมัครงานแล้วเขาขอ OTP แบบนี้ปลอดภัยไหม?” ให้คำแนะนำด้านความปลอดภัยได้เมื่อข้อความไม่มีรหัสจริง คำถามเรื่องค่ามัดจำให้เตือนและเสนอขั้นตอนตรวจประกาศหรือนายจ้าง
2. อ่านเรื่องที่ผู้ใช้กำลังคุย คำถามล่าสุดที่แอปถาม และคำตอบที่ใช้ได้ในโปรไฟล์ ถ้าข้อความเปิดเรื่องใหม่ชัดเจน ให้เปลี่ยนไปเรื่องนั้นก่อนพยายามตีความว่าเป็นคำตอบของข้อที่ค้าง
3. ถ้าผู้ใช้กดปุ่มหรือระบุเจตนาชัดเจน ให้เลือก **เช็กสิทธิ** หรือ **วางแผนหาเงินเพิ่ม** โดยตรง เช่น “เบี้ยไม่เข้า” อยู่ในเรื่องเช็กสิทธิ และ “มีอะไรให้ทำจากบ้านบ้าง” อยู่ในเรื่องหาเงินเพิ่ม ถ้ายังแยกไม่ได้ ให้ถาม **“อยากเริ่มจากเช็กสิทธิรับเงิน หรือวางแผนหาเงินเพิ่ม?”** คำขอที่อยู่นอกขอบเขตอย่างชัดเจนให้ตอบสั้น ๆ และเสนอทางกลับเข้าแอป เมื่อมีคำขอในขอบเขตผสมกับเรื่องทั่วไป ให้เดินต่อด้วยส่วนที่เกี่ยวข้องหลังผ่านการตรวจข้อความ
4. อ่านคำตอบสั้น เช่น “ยังไม่ได้ค่ะ” ตามคำถามที่ผู้ใช้เห็นล่าสุด ถ้าผู้ใช้ต้องการติดตามเบี้ยและยังไม่รู้สถานะการรับ ให้ถาม “ตอนนี้ได้รับเบี้ยอยู่แล้วไหม?” คำตอบ “ยังไม่ได้ค่ะ” สำหรับข้อนี้คือ `oldAgeGets = false` ถ้าข้อที่ค้างคือช่วงอายุ ให้แสดงตัวเลือกช่วงอายุอีกครั้ง ถ้าแหล่งข้อมูลเพิ่งเติมคำตอบให้ ให้ปิดคำถามเดิมและประมวลข้อความล่าสุดต่อ ข้อความที่ตอบคำถามเดิมต้องผูกกับข้อเดิมก่อนตรวจว่าค่ายังใช้ได้
5. ถามทีละข้อเฉพาะเมื่อคำตอบเปลี่ยนผลเช็กสิทธิหรือขั้นตอนถัดไป ผู้ใช้เลือก **ไม่แน่ใจ** ได้ทุกข้อ ข้ามข้อนั้นในรอบนี้และคัดกรองต่อด้วยข้อมูลที่มี

ให้ server เก็บหัวข้อที่เลือก รหัสคำถามบนจอ คำถามที่ข้าม และเป้าที่ยังคุยไม่จบไว้กับเจ้าของบทสนทนา คำนวณใหม่จากโปรไฟล์ทุกเทิร์น เก็บยอดเงินกับชนิดเป้าแยกกัน เมื่อถามชนิดเป้าแล้วผู้ใช้ตอบเพียง “รายเดือน” ให้ใช้ยอดที่เพิ่งคุยกัน ถ้าผู้ใช้แก้เป็น “เงินก้อน 3,500” ให้แทนยอดเฉพาะรอบนี้ การแก้ตัวเลขในแชทจะเปลี่ยนเป้าถาวรได้เมื่อผู้ใช้กดยืนยัน

| สิ่งที่ผู้ใช้กำลังขอ | การตัดสินใจที่ต้องเห็นในแอป |
| --- | --- |
| “สิ้นเดือนนี้ยังขาดค่าเช่าห้อง” | รับบริบทค่าเช่า แล้วชวนเลือก “ลองเช็กสิทธิที่อาจช่วยได้” หรือ “หาทางหาเงินเพิ่ม” จะถามยอดที่ขาดแทนก็ได้ถ้าเปิดทางให้คนที่ยังไม่รู้ยอดไปต่อ |
| “ช่วยเช็กให้แม่ แม่อายุ 72” / “ต้องดูแลแม่ อยากหางานทำจากบ้านให้ตัวเอง” | ข้อแรกอธิบายว่าแอปประเมินให้เจ้าของโปรไฟล์และเว้นอายุแม่จาก facts กับ LLM ข้อหลังใช้การทำงานจากบ้านเป็นเงื่อนไขของเจ้าของโปรไฟล์ ถ้าบอกเพียง “อายุ 72” และยังไม่ชัดว่าพูดถึงใครหลังเพิ่งคุยถึงแม่ ให้ถามว่าเป็นอายุของผู้ใช้หรือไม่ |
| เจตนายังคลุมเครือ | แสดงคำถามช่วยเลือกพร้อมปุ่ม หน้า Flutter ใช้ป้ายผู้ช่วยตามปกติ ป้าย “นอกเรื่อง” ใช้เมื่อคำขออยู่นอกขอบเขตชัดเจน หากถามชี้ทางหนึ่งครั้งแล้วยังตอบไม่ได้ ให้เปิดทางดูสิทธิหรือทางหาเงินจากปุ่มได้ทันที |
| ส่งรหัสลับจริง | Guard กันก่อนเข้า LLM และประวัติ ฝั่ง Flutter ล้างช่องพิมพ์แล้วแสดงข้อความรอตรวจที่ไม่มีเนื้อหาดิบ เมื่อผลเป็น `sensitive` ให้เก็บเพียงข้อความแทนใน ChatSession รวมถึงเมื่อออกแล้วกลับเข้าแชท กรณีเครือข่ายขัดข้องยังคงซ่อนข้อความที่รอตรวจ |

## ฟิลด์ที่เก็บและคำถามที่ข้ามได้

ชื่อด้านล่างเป็นฟิลด์ภายในทางรอด ฟิลด์ที่เพิ่มจากเดโมใช้ได้เมื่อได้รับชุดข้อมูลจากหน่วยงานเจ้าของข้อมูลและมีสิทธิ์เข้าถึงในโปรไฟล์นั้น. [ตัวเติมข้อมูลเดโม](../../contracts/adapters/gov-prefill-demo.js#L5) · [ตัวอย่างข้อมูลทั้งสี่แหล่ง](../../contracts/fixtures/gov-prefill-demo.json#L13) · [ฟิลด์คำตอบเดิม](../../contracts/fixtures/reference.json#L122)

| บริการ | ฟิลด์ที่เก็บ | ข้ามคำถามเมื่อใด | แสดงที่ ฉัน > โปรไฟล์ |
| --- | --- | --- | --- |
| **ThaID** `thaid` | เดโมใช้ `ageBand` และข้อมูลชื่อกับเขตเพื่อแสดงโปรไฟล์ สำหรับข้อมูลจริงใช้วันเกิดในข้อมูลยืนยันตัวตนที่จำกัดสิทธิ์ หรือเก็บช่วงอายุพร้อมวันที่อ้างอิงถ้าได้รับเพียงช่วงอายุ เก็บ `registryDistrict` และ `registryProvince` เมื่อได้รับที่อยู่ตามทะเบียนบ้าน เก็บ `nationality` เมื่อได้รับโดยตรง | ข้ามคำถามอายุเมื่อคำนวณอายุตามวันตัดสิทธิได้ หรือช่วงอายุที่มีตอบเกณฑ์นั้นได้ ข้ามคำถามทะเบียนบ้านและสัญชาติตามฟิลด์ที่ได้รับ ช่วงอายุ `ต่ำกว่า 60` ยังต้องถามว่าครบ 55 หรือไม่เมื่อคัดกรองชราภาพ | ชื่อ อายุ และพื้นที่ทะเบียนบ้าน แสดงเขตที่ใช้หางานเป็นอีกช่องหนึ่ง |
| **ทางรัฐ** `tangRat` | เก็บ `disabilityCardStatus` และคำนวณ `disabilityCard` เดโมรองรับสถานะบัตรที่ยังใช้ได้ สำหรับข้อมูลจริง ให้ใช้ `false` เมื่อหน่วยงานระบุชัดว่าบัตรใช้ไม่ได้หรือไม่มีบัตร หากไม่ได้รับสถานะ ให้คงเป็น **ไม่ทราบ** เก็บ `oldAgeGets` หรือ `disabilityGets` เมื่อได้รับสถานะผู้รับเบี้ยของรายการนั้น | ข้าม “มีบัตรคนพิการที่ยังใช้ได้ไหม?” เมื่อรู้สถานะบัตร ข้าม “ได้รับเบี้ยอยู่แล้วไหม?” เมื่อรู้สถานะผู้รับเบี้ยของสิทธินั้น ให้ประเมินเบี้ยพื้นฐานจากข้อมูลที่มี ถ้าต้องประเมินเงินเพิ่มและยังขาด `welfareCard` ค่อยถามข้อนี้ | สถานะบัตร และสถานะรับเบี้ยแยกรายการเมื่อมีข้อมูล |
| **ประกันสังคม** `socialSecurity` | เก็บ `coverageSectionAtExit`, `employmentEndedAt` เมื่อมี และข้อมูลสมทบช่วงก่อนออกงาน `windowMonthsBeforeExit`, `paidMonths`, `complete` คำนวณ `ss33` ตามเงื่อนไขเดิมของทางรอด ถ้ามีข้อมูลชราภาพให้เก็บ `coverageStatus`, `coverageEndedAt` และ `lifetimePaidMonths33And39` พร้อมขอบเขตช่วงที่ตรวจ | ข้าม “ส่งครบ 6 เดือนใน 15 เดือนก่อนออกงานไหม?” เมื่อ `ss33` มาจากประวัติ ม.33 ที่ครบช่วงก่อนออกงาน สำหรับชราภาพให้ข้ามเรื่องสิ้นสุดผู้ประกันตนและเดือนสะสมเฉพาะเมื่อมีฟิลด์ชราภาพที่ตอบข้อนั้น | มาตรา สถานะ และสรุปเดือนสมทบพร้อมช่วงที่นับ |
| **D-MyTax** `dMyTax` | เก็บ `taxYear` เป็น ค.ศ. และสถานะ `taxWithheld` ถ้าใช้ยอดประกอบการตรวจ ให้เก็บในรายละเอียดภาษีพร้อมช่วงและความครบถ้วนของข้อมูล | ข้าม “ปีนี้มีภาษีหัก ณ ที่จ่ายไหม?” เมื่อข้อมูลตรงปี ยอดบวกใช้ตอบว่ามีได้ การตอบว่าไม่มีจากยอดศูนย์ต้องอาศัยข้อมูลที่ยืนยันว่าครบ ยอดหักใช้ประกอบการตรวจเงินคืน | ปีภาษีและสถานะภาษีหัก ณ ที่จ่าย แสดงยอดในรายละเอียดภาษีเมื่อมี |

เก็บแหล่งที่มา สถานะข้อมูลจริงหรือจำลอง วันที่ข้อมูลมีผล และช่วงเวลาที่ครอบคลุมไว้กับแต่ละค่า อ่านคำตอบเดิมจาก `/v1/me/facts` และ `/v1/me/profile` ค่า `false` ที่ยืนยันแล้วเป็นคำตอบที่ใช้ได้ ถ้าหน่วยงานไม่ส่งค่า ให้ใช้คำตอบเดิมที่ยังตรงช่วงเวลา หรือคงสถานะ **ไม่ทราบ** เมื่อแหล่งข้อมูลกับคำตอบของผู้ใช้ขัดกัน ให้ถามเฉพาะข้อที่กระทบผล และเก็บคำตอบของผู้ใช้พร้อมที่มา หากข้ามข้อจำเป็น ให้คงผลของรายการนั้นเป็น **ข้อมูลไม่พอ** หรือ **ต้องตรวจต่อ** และเว้นจากยอดที่คาดว่าจะได้รับ

เมื่อยกเลิกการเชื่อม ให้หยุดใช้ค่าจากแหล่งนั้นทันที ใช้คำตอบที่ผู้ใช้เคยให้ไว้ถ้ายังใช้ได้ และประเมินผลใหม่ รวมถึงคำถามที่ค้างอยู่ แอปรับผลอัปเดตเมื่อข้อมูลยังตรงกับบัญชีและการเชื่อมรอบปัจจุบัน

ตรวจความใช้ได้ตามฟิลด์ วันเกิดใช้คำนวณใหม่ ณ วันที่สิทธิกำหนด ภาษีต้องตรงปีภาษี เงินสมทบก่อนออกงานต้องตรงเหตุการณ์ออกงานที่กำลังตรวจ แม้ประวัติของงานก่อนหน้านั้นจะครบ 15 เดือนก็ตาม สถานะที่เปลี่ยนได้ เช่น บัตร เขตทะเบียนบ้าน หรือการรับเบี้ย ให้ใช้วันมีผลและวันหมดอายุที่แหล่งระบุ หากชุดข้อมูลจริงยังไม่มีเกณฑ์ความใหม่ที่ตกลงไว้ ให้แสดงค่าเดิมพร้อมวันที่อ้างอิงและขอให้ผู้ใช้ยืนยันก่อนใช้ค่านั้นข้ามคำถาม การรีเฟรชที่ล้มเหลวให้นำเกณฑ์เดิมมาประเมินข้อมูลที่เก็บไว้

ในโหมดเดโม ให้ใช้ข้อมูลจำลองของแหล่งที่เลือกและติดป้าย **DEMO / MOCK** คำตอบตั้งต้นใน persona เช่น เหตุออกจากงานและค่าจ้าง เป็นของฉากทดสอบ ให้ใช้เป็นคำตอบของ persona เท่านั้น. ### เกณฑ์ที่ให้ DEV ใช้ตัดสินทีละฟิลด์

ประเมินตามลำดับด้านล่าง ก่อนเลือกคำถาม ก่อนคำนวณยอด และก่อนสร้างบริบทส่งโมเดล ทั้งหน้าคัดกรองแบบปุ่ม แชท และแผนรายได้ต้องอ่านผลประเมินเดียวกัน

| ลำดับ | ตรวจอะไร | เมื่อใช้ค่านั้นไม่ได้ |
| --- | --- | --- |
| 1 | ฟิลด์เกี่ยวกับเรื่องที่ผู้ใช้เลือก เช่น ขอเช็กเงินคืนภาษีของปี 2569 | ตัดฟิลด์ของเรื่องอื่นออกจากคำถามและบริบท |
| 2 | ค่าที่มาจากบริการอยู่ในบัญชี โหมดเดโม/ผู้ใช้จริง การเชื่อมรอบปัจจุบัน และชุดฟิลด์ที่อนุญาต | ทิ้งค่าจากรอบนั้นก่อนแตะโปรไฟล์ ตรวจคำตอบจากผู้ใช้ที่มีที่มาเป็นอิสระ |
| 3 | ชนิดค่า ความครบถ้วน ปีภาษี เหตุการณ์ออกงาน หรือวันที่มีผล ตรงกับเกณฑ์ของข้อนี้ | ค่าเก่าใช้แสดงย้อนหลังตามสิทธิ์เข้าถึงได้ ถ้าเกี่ยวกับผลให้ถามเฉพาะข้อนี้ สถานะ **ไม่มีข้อมูล** กับคำตอบ **ไม่มี** แสดงคนละข้อความ |
| 4 | ค่าที่เหลือจากผู้ใช้และบริการสอดคล้องกัน หรือผู้ใช้เคยยืนยันความขัดกันของข้อมูลชุดนี้แล้ว | ถามยืนยันหนึ่งครั้ง ผู้ใช้ตอบแล้วให้เก็บว่า “คุณยืนยัน” พร้อมหัวข้อและวันที่ เมื่อข้อมูลต้นทางรุ่นใหม่เปลี่ยนความหมายจึงตรวจอีกครั้ง ถ้าข้ามให้คงผล “ต้องตรวจต่อ” |
| 5 | มีคำตอบที่ใช้ได้จริง รวมถึง `false` และศูนย์ที่ครบเงื่อนไข | ถ้ามี ให้ข้ามข้อนั้น ถ้าขาด ให้ถามเกณฑ์แรกที่เปลี่ยนผลหรือการประมาณยอดของเรื่องที่เลือก ถ้าข้อมูลพอแล้วให้แสดงผลและวิธีไปต่อ |

ใช้วันอ้างอิงของสิทธิแยกจากเวลาที่ดาวน์โหลด ตรวจภาษีตามปีที่ถาม เช่น พ.ศ. 2569 ตรงกับ ค.ศ. 2026 เก็บหลักฐานภายในต่อฟิลด์ให้ตามกลับได้ถึงแหล่ง/คำตอบ เจ้าของ เหตุการณ์หรือช่วงที่ใช้ได้ วันที่มีผล วันที่ตรวจ และรุ่นข้อมูล เมื่อผู้ใช้ขอเลิกเชื่อม ให้ตัดข้อมูลที่มาจากบริการนั้นออกจากคำตอบปัจจุบันและการส่งเข้าโมเดลทันที ผลที่กลับมาภายหลังใช้ได้เฉพาะเมื่อยังตรงการเชื่อมรอบที่เริ่มคำขอนั้น

## การเชื่อมครบ เชื่อมบางตัว และยังไม่เชื่อม

| กรณี | ข้อมูลที่มี | สิ่งที่แอปถามหรือทำก่อนส่ง LLM |
| --- | --- | --- |
| **เชื่อมครบ** | ThaID มีช่วงอายุ 60–69 และเขตตามทะเบียน ทางรัฐมีบัตรคนพิการ ประกันสังคมมีประวัติสมทบครบช่วง และ D-MyTax มีข้อมูลปีที่ตรวจ | เมื่อผู้ใช้เลือก **เช็กสิทธิ → เบี้ยผู้สูงอายุ** ให้ใช้ช่วงอายุและเขต ถ้ายังไม่รู้สัญชาติ ให้ถามเรื่องสัญชาติก่อน แล้วประเมินว่าต้องถามเรื่องเงินประจำจากรัฐหรือเคยรับเบี้ยต่อหรือไม่ ข้อมูลของอีกสามบริการพร้อมใช้เมื่อเกี่ยวกับเรื่องที่ถาม |
| **เชื่อมบางตัว** | เชื่อม ThaID กับประกันสังคม มี `ss33 = true` และผู้ใช้เคยกรอกว่าออกจากงานแล้ว | เมื่อผู้ใช้เลือก **เช็กสิทธิ → เงินว่างงาน** ให้ข้ามคำถามสมทบและสถานะงาน ถ้าเหตุออกจากงานในโปรไฟล์ละเอียดพอและยังไม่ทราบค่าจ้าง ให้ถามค่าจ้างล่าสุดเพื่อประมาณยอด ถ้าผู้ใช้เปลี่ยนไปถามเรื่องภาษี ให้ตรวจคำตอบเดิมในโปรไฟล์ก่อนถามเรื่องภาษีหัก ณ ที่จ่าย |
| **ยังไม่เชื่อม** | ผู้ใช้กรอกช่วงอายุ 70–79 ไว้แล้ว แต่ยังไม่มีข้อมูลทะเบียนบ้านและสัญชาติ | เมื่อผู้ใช้เลือก **เช็กสิทธิ → เบี้ยผู้สูงอายุ** ให้ข้ามคำถามอายุ ถามเกณฑ์ข้อแรกที่ยังขาดและใช้ผลประเมินระหว่างตอบ ถ้าโปรไฟล์ว่าง แอปเริ่มจากช่วงอายุได้ ผู้ใช้ข้ามข้อที่ไม่แน่ใจและดูขั้นตอนตรวจต่อได้ |

สำหรับ **วางแผนหาเงินเพิ่ม** ทั้งสามกรณีใช้คำตอบจากแชทและโปรไฟล์เรื่อง `incomeGoalPerMonth`, `skills`, `hoursPerWeek`, `constraints` และเขตหางาน ข้อมูลจากสี่บริการใช้เมื่อผู้ใช้ต้องการรวมเงินที่อาจมีสิทธิรับไว้ในแผน

เมื่อจบคำถามก่อนส่งต่อ ให้แต่ละกรณีส่งผลเท่าที่ตรวจได้ ตัวอย่างเช่น **เชื่อมครบ** ส่งผลเช็กเบี้ยผู้สูงอายุและขั้นตอนของพื้นที่ตามทะเบียน **เชื่อมบางตัว** ส่งผลเช็กเงินว่างงานจากข้อสมทบและค่าจ้างที่ผู้ใช้ตอบ และ **ยังไม่เชื่อม** ส่งผลจากคำตอบของผู้ใช้พร้อมระบุว่าเรื่องไหนยังต้องตรวจ ถ้าผู้ใช้ข้ามคำถามสัญชาติ ให้ส่งว่ายังขาดสัญชาติและให้ LLM อธิบายวิธีตรวจต่อได้

## รับเป้าหมายเงินจากภาษาที่ผู้ใช้พูด

เก็บจำนวนเงินที่ผู้ใช้ระบุไว้ในบทสนทนา รวมกับรูปแบบเป้าหมาย **เงินก้อน**, **รายเดือน** หรือ **ยังไม่ทราบ** เก็บกำหนดใช้เงินเมื่อมี ให้ใช้แผนรายเดือนเดิมเมื่อผู้ใช้ยืนยันเป้ารายเดือน ส่วนเงินก้อนใช้เวลาและข้อมูลที่มีเสนอทางเลือกกับขั้นตอนถัดไป

อ่านเลขไทย เลขอารบิก ตัวคั่นหลักพัน และจำนวนที่เขียนเป็นคำในตัวอย่างที่รองรับ ผูกยอดกับคำอย่าง “ได้อยู่” “อยากมีเพิ่ม” และ “ต่อเดือน” หากผู้ใช้ปฏิเสธยอดเดิม ให้ถามยอดใหม่หรือช่วยทบทวนเป้า ก่อนเรียกแผนรายเดือนให้ตรวจว่าจำนวนเป็นบวกและอยู่ในช่วงที่ตัววางแผนรับได้ ปัจจุบันรับได้สูงสุด 1,000,000 บาทต่อเดือน หากค่าอยู่นอกช่วง ให้ถามจำนวนใหม่โดยคงข้อความเดิมไว้ในรอบสนทนา

ใช้เวลา `Asia/Bangkok` เมื่อแปลง “สิ้นเดือน” และ “พรุ่งนี้” ราคาหรือวันที่ที่ตีความได้หลายทางให้ถามยืนยันครั้งเดียว หากกำหนดใช้เงินผ่านไปแล้วให้ถามกำหนดใหม่

| ผู้ใช้พูด | การตอบและการใช้ข้อมูล |
| --- | --- |
| “อยากได้ตัง 5000 หาให้หน่อยดิ๊” | รับเป้า 5,000 บาท แล้วถาม **“ต้องการ 5,000 บาทเป็นเงินก้อน หรืออยากมีเพิ่มเดือนละ 5,000 บาท?”** ตอบได้ด้วยปุ่มและยังสามารถพิมพ์ต่อ |
| “อยากได้เงินเดือนละ 5,000 บาท” | ใช้เป้า 5,000 บาทต่อเดือนกับ `plan_income_goal` และข้อมูลโปรไฟล์ที่มี |
| “เห็นคนพูดถึงเงินช่วยเหลือ 5,000 บาท ฉันมีสิทธิ์โครงการนี้ไหม” | ตัวเลขขยายคำว่าเงินช่วยเหลือ ให้ถามชื่อโครงการหรือประกาศเพื่อเช็กสิทธิ เก็บจำนวนไว้กับคำขอเช็กสิทธิ และเว้นจากเป้ารายได้ของผู้ใช้ |
| “หาเงินห้าพันจ่ายค่าเช่าสิ้นเดือน” | ใช้เป้าเงินก้อน 5,000 บาทพร้อมกำหนดสิ้นเดือน เมื่อมีหลายยอดให้ผูกยอดกับค่าใช้จ่ายหรือเป้าที่ระบุ ถ้ายังแยกไม่ได้ให้ถามยืนยันยอด |
| “มีอะไรให้ทำจากบ้านบ้าง เดินไกลไม่ไหว” | เปิดเรื่องหาเงินเพิ่ม ใช้เงื่อนไขทำจากบ้านและข้อจำกัดการเดินทางในรอบนี้ ถ้าข้อมูลพอให้เสนอทางเลือก ถ้ายังขาดให้ถามเฉพาะทักษะหรือเวลาว่างข้อที่ช่วยเลือกงาน |
| “ยังไม่รู้ว่าอยากได้เท่าไหร่” | ถาม **“มีค่าใช้จ่ายเรื่องไหนที่อยากให้เงินส่วนนี้ช่วยก่อน?”** และให้ดูทางเลือกได้แม้ยังไม่มีตัวเลข |
| “อายุ 65 แล้ว เบี้ยไม่เข้า ทำยังไงดี” | จับทั้งอายุและเรื่องเงินไม่เข้า ถามว่าเคยรับเบี้ยอยู่แล้วหรือยังถ้าไม่รู้ แล้วไปเส้นทางติดตามเงินจ่ายหรือวิธียืนยันสิทธิตามกรณี |

ถ้าผู้ใช้ยังไม่ได้ระบุยอดและมีเป้ารายเดือนในโปรไฟล์ ให้เสนอ **ใช้เป้าเดิม** หรือ **เปลี่ยนเป้าหมาย** เมื่อตั้งเป้าใหม่จากแชท ให้ใช้ยอดนั้นในรอบนี้ และให้ผู้ใช้ยืนยันก่อนบันทึกเป็นเป้าในโปรไฟล์

## สัญญาการทำงานระหว่าง guard กับ LLM

ในแต่ละเทิร์นให้ตัดสินว่าพร้อมส่งต่อหรือยัง โดยดูผลที่ผู้ใช้ต้องการ ตัวอย่างด้านล่างใช้ข้อมูลสมมติ

| สถานะ | ถามหรือส่งอะไร | ตัวอย่าง |
| --- | --- | --- |
| ยังไม่รู้ว่าจะช่วยเรื่องไหน หรือขาดค่าที่เปลี่ยนผล | ส่งคำถามหนึ่งข้อพร้อมตัวเลือกให้ Flutter จำนวนครั้งเรียกโมเดลเป็นศูนย์เมื่อกฎเลือกคำถามได้ | รู้อยู่แล้วว่าอยากได้ 5,000 แต่ยังไม่รู้ช่วงเวลา ถามเฉพาะเงินก้อนหรือรายเดือน |
| ข้อมูลพอสำหรับกฎ | เรียกเครื่องมือเฉพาะเรื่องนั้นแล้วคืนผล ผู้ใช้ขอคำอธิบายเพิ่มเติมจึงส่งผลที่คำนวณแล้วให้ผู้ช่วยเรียบเรียงได้ | D-MyTax ตรงปีและยืนยันการหักภาษีแล้ว แสดงวิธีตรวจยอดคืนจริงของปีนั้น |
| ต้องการให้ช่วยคิด หรือเลือกข้ามข้อที่ยังขาด | เมื่อยินยอมใช้ AI ส่งเจตนา เป้า ข้อจำกัดหรือผลที่จำเป็นต่อคำขอนั้น พร้อมระบุข้อที่ยังประเมินไม่ได้ | ขอไอเดียหาเงินจากบ้าน ส่งทักษะทำอาหาร เวลาว่าง และข้อจำกัดทำงานที่บ้าน ชื่อ ข้อมูลภาษี วันเกิด และประวัติสมทบไม่เข้า payload |
| รู้หัวข้อแต่ประโยคอ่านได้หลายแบบ | หากถามให้เลือกความหมายได้ด้วยกฎ ให้ถามหนึ่งข้อ เมื่อจำเป็นต้องใช้โมเดลช่วยตีความ ให้ตรวจคำตอบที่เสนอแล้วรอผู้ใช้ยืนยันส่วนที่กำกวม | “มีอยู่ 500 อยากให้ถึงห้าพัน” ถ้ายังไม่รู้ว่า 5,000 คือยอดรวมที่อยากมีหรือยอดที่อยากได้เพิ่ม ให้ถามก่อนคำนวณ |

- ใช้ `POST /v1/ai/conversations` กับเส้นทางส่งข้อความเดิม ให้ server เลือกเจตนาและคำถามปัจจุบัน หน้า Flutter แสดงคำถามและปุ่มที่ server ส่งมา ใช้ตัวประเมินสิทธิเดิมประเมินจาก facts ที่ใช้ได้ในรอบนั้น เมื่อผู้ใช้ขอสองเรื่องในข้อความเดียว ให้ใช้ลำดับที่เขาระบุ ถ้ายังไม่มีลำดับ ให้ถามว่าจะเริ่มเรื่องไหนและเก็บอีกเรื่องไว้ในบทสนทนา เช่น เช็กคืนภาษีควบคู่กับเป้าหาเงินเพิ่ม 5,000 บาท
- คง `text` และ `quickReplies` ใน API เดิม เพิ่ม `step.id` สำหรับคำถามที่แอปแสดง และรับ `stepId` แบบไม่บังคับเมื่อผู้ใช้ตอบจากคำถามนั้น ใช้รหัสเดิมเฉพาะตอนส่งคำถามเดิมซ้ำ ถ้า `stepId` หมดอายุ ให้คำนวณสถานะปัจจุบันและแสดงคำถามที่ถูกต้อง คำตอบต่อคำถามเก่าจะไม่เปลี่ยน facts ของข้อใหม่ ส่วนข้อความที่เริ่มเรื่องใหม่ชัดเจนให้ดำเนินต่อได้ แอปเวอร์ชันเดิมยังส่ง `text` อย่างเดียวได้ เมื่อไม่แน่ใจว่าคำตอบสั้นอ้างถึงข้อไหน ให้ถามยืนยัน. [สัญญา API ปัจจุบัน](../../contracts/openapi.yaml#L413)
- ในคำถามรายสิทธิ ให้ส่ง `step.moneyId`, `step.fact` และ `step.question` ตามสัญญาเดิม พร้อมคำถามที่อ่านได้ใน `reply` เมื่อคำตอบครบแล้วให้จบการถามหัวข้อนั้นและสรุปเฉพาะสิทธิที่เลือก เมื่อผู้ใช้กดปุ่มซ้ำให้ตรวจเจ้าของบทสนทนาและสถานะของคำถามภายในการบันทึกเดียวกัน แล้วคืนคำถามล่าสุด การแตะซ้ำต้องให้ผลเดิมแม้เกิดพร้อมกัน
- เมื่อมีคำถามที่จำเป็นและถามได้ด้วยกฎ ให้คืนคำถามและตัวเลือกจาก server โดยไม่เรียก LLM รวมถึงปุ่มข้าม คำตอบที่ตรงตัวเลือก หรือยอดที่ระบุหน่วยและช่วงชัดเจน เลิกใช้ `ai.extract()` เป็นทางเข้าปกติสำหรับคำตอบที่กำลังคัดกรอง
- เมื่อพร้อมอธิบายผลหรือช่วยคิดทางเลือก ให้ส่งเจตนา เป้าและช่วงเวลา ข้อจำกัดเท่าที่จำเป็น ผลจากกฎหรือเครื่องมือ และรายการข้อมูลที่ยังไม่ทราบ ส่งเฉพาะข้อมูลที่จำเป็นต่อสิ่งที่ผู้ใช้ขอ ประวัติดิบจากบริการ เลขบัตร วันเกิดเต็ม ที่อยู่เต็ม และข้อมูลลับอยู่หลังขอบเขตนี้
- เมื่อรู้ว่าเรื่องอยู่ในขอบเขตจากข้อความหรือหัวข้อที่ผู้ใช้เลือก แต่กฎอ่านรายละเอียดไม่ได้ ให้ LLM เสนอความหมายจากข้อความที่ผ่านการตรวจและบริบทช่วงสั้น ๆ เช่น ยอดใดคือเป้า หรือผู้ใช้หมายถึงสิทธิรายการไหน ให้โมเดลคืนค่าที่เสนอพร้อมข้อที่ยังไม่ชัด แล้วให้ server ตรวจชนิดและช่วงของค่า ถ้าความหมายยังเปลี่ยนผลได้หลายทาง ให้แอปถามยืนยันหนึ่งข้อก่อนใช้ค่านั้นคำนวณหรือบันทึก
- ให้ LLM ช่วยแนะนำและพูดภาษาที่เข้าใจง่าย ให้ server เป็นผู้เลือกคำถามถัดไป ตรวจข้อมูลก่อนบันทึก และคำนวณสิทธิหรือยอดจากข้อมูลต้นทาง แสดงลิงก์และเบอร์ติดต่อจากผลเครื่องมือที่ตรวจสอบได้ หากไม่มีข้อมูล ให้บอกผู้ใช้ว่าจะตรวจช่องทางต่อได้อย่างไร การบันทึกแผนและการแก้โปรไฟล์ใช้การยืนยันของผู้ใช้
- ถ้า LLM ปิดหรือใช้ไม่ได้ ให้ใช้คำถามชี้ทาง ปุ่มช่วยเลือกเป้าหมาย ผลคัดกรอง และช่องทางที่มีอยู่ เป้าก้อนเดียวที่ยังประมาณยอดไม่ได้ให้แสดงทางเลือกและขั้นตอนที่ผู้ใช้ทำได้ตามเวลาที่แจ้ง หากผู้ใช้ยังไม่ยินยอมใช้ AI ให้มีทางเข้าเช็กเงินและแผนรายได้แบบใช้กฎจากหน้าแอป โดยใช้ข้อกำหนดความยินยอมเดิมของเส้นทางแชท AI
- ถ้าถอนความยินยอมระหว่างรอ ให้ตรวจสิทธิ์และรุ่นข้อมูลอีกครั้งก่อนแสดงผล เก็บความจำ หรือเสนอการบันทึกจากผลเก่า ยกเลิกคำขอที่ยังยกเลิกได้ และทิ้งผลที่หมดสิทธิ์ใช้ ถ้าคำขอออกจากระบบไปแล้ว การถอนมีผลกับการใช้ผลและคำขอถัดไป

## งานที่ dev ต้องทำและเกณฑ์ตรวจรับ

1. เพิ่มข้อมูลแหล่งที่มาและช่วงเวลาให้ facts ในโปรไฟล์ แล้วผูกตัวเติมของสี่บริการกับคำถามในระบบเดิม
2. ปรับ handler แชทให้รู้เจตนาก่อนเลือกคำถามค้าง และกำหนดให้เป้ารายเดือนกับเป้าเงินก้อนเดินคนละขั้น เพิ่มปุ่มถามกลับในหน้าแชทตาม response จาก server
3. ปรับหน้า **ฉัน > โปรไฟล์** ให้เห็นค่าที่นำไปใช้ พร้อมแหล่งที่มาและวันที่ตรวจล่าสุด ใช้หน้า **บัญชีที่เชื่อมต่อ** สำหรับจัดการการเชื่อม. [เมนูบัญชีที่เชื่อมต่อ](../../app/lib/me_tab.dart#L342)
4. รัน `contracts/test-thang-rot-guard.js` และ regression เดิม พร้อมทดสอบปุ่มกับคำถามในแชท Flutter หากปรับ `assistant-policy.json` ให้ซิงก์และรัน smoke test ของ mockup ด้วย. [แผนตรวจรับ](thang-rot-guard-test-spec.md) · [นโยบายแชทเดิม](../design/ai-agent.md#L29)

| AC-12 | พูดถึงคนในครอบครัวแล้วระบบแยกเจ้าของความต้องการได้ ถ้ายังไม่ชัดให้ถามว่าเป็นเรื่องของใคร ข้อมูลของบุคคลอื่นไม่เข้าคำตอบหรือโมเดล |
| AC-13 | ผู้ใช้ที่บอกเพียงภาระค่าใช้จ่ายได้รับคำถามช่วยเลือกเรื่อง เมื่อระบุยอดในเทิร์นหนึ่งและตอบชนิดเป้าในอีกเทิร์น ระบบใช้ยอดล่าสุด เป้าถาวรคงเดิมจนกดยืนยัน |
| AC-14 | จากแชท Flutter ปุ่มส่งรหัสของคำถามที่เห็นจริง คำถามชี้ทางไม่มีป้ายนอกเรื่อง และรหัสลับไม่ปรากฏในฟองคำพูดทั้งตอนรอผลและตอนกลับเข้าแชท |
