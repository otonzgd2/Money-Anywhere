เงินที่คนควรได้มีอยู่จริง แต่คนไปไม่ถึง

1

ไม่รู้ว่ามีสิทธิ์

สิทธิ์กระจายอยู่หลายหน่วยงาน: พม., ประกันสังคม, กรมสรรพากร, กรมบัญชีกลาง, อปท., คปภ., กอช. ฯลฯ คนส่วนใหญ่รู้แค่ว่า "เกิดอะไรกับตัวเอง" ไม่รู้ชื่อโครงการ

2

รู้แล้วก็ทำไม่จบ

ไม่รู้ว่าต้องใช้เอกสารอะไร ยื่นที่ไหน ต้องมี ThaID / พร้อมเพย์ผูกบัตรไหม ไม่ผ่านแล้วทำอะไรต่อ

3

ข้อมูลรัฐรายบุคคลยังไม่เปิดให้ใช้

ThaID และ GDX ต้องมีข้อตกลงกับหน่วยงาน นักพัฒนาทั่วไปเรียกเองไม่ได้

4

AI ตอบเร็ว แต่ตัวเลขเงินเชื่อไม่ได้

ถ้าให้ AI บอกยอดเงินเอง เสี่ยงสัญญาเงินที่ไม่มีจริง

สถาปัตยกรรม

แอปคุยกับสัญญา (contract) อย่างเดียว ส่วนข้างหลังสลับได้

แอปไม่รู้จัก Gemini, ไฟล์เก็บข้อมูล หรือแหล่งงาน รู้แค่ contract → เปลี่ยนข้างหลังได้โดยไม่แก้แอป4
Logic 1 · money engine

กฎเงินเป็น "ข้อมูล" ไม่ใช่โค้ด: ผลเหมือนเดิมทุกครั้ง ตรวจย้อนได้

Input → Output

Input: คำตอบของผู้ใช้ (facts) เช่น อายุ, ประกันสังคม ม.33, ถูกเลิกจ้าง, ทำงาน 7 ปี, ค่าจ้าง 15,000

Rules: reference.json → moneyPrograms มีเงื่อนไข อัตรา เอกสาร ช่องทาง และ sources + checkedAt

Output ต่อรายการ: ผล + ยอด + basis (มาจากอะไร) + แหล่งอ้างอิง + ขั้นตอนถัดไป

ผลมี 4 แบบ (และ 1 แบบที่สงวนไว้)

likely น่าจะได้check ต้องเช็คยอดจริงneed ตอบอีกข้อunlikely ไม่น่าได้verified เฉพาะ gov adapter

ไม่มีคำว่า "ได้แน่นอน" ระบบไม่สัญญาเงิน

adapter: contracts/adapters/money.js · ตัวอย่างนี้อยู่ใน mockup บริการรัฐ (ยังไม่อยู่ใน API)5
Logic 2 · ถามเท่าที่จำเป็น

ถามทีละข้อ เฉพาะข้อที่เปลี่ยนผลได้ แล้วคิดใหม่ทันที

ทำไมเป็นจุดแข็ง

  • ไม่มีฟอร์มยาว ผู้ใช้ตอบแค่ข้อที่ส่งผลต่อเงินของเขา
  • ทุกคำถามมีคำอธิบาย (help) กด "ไม่เข้าใจ" แล้ว AI อธิบายข้อนั้นได้
  • ตอบ "ไม่แน่ใจ" ได้ ผลกลายเป็น check พร้อมบอกวิธีเช็ค ไม่ติดค้าง
  • ถามซ้ำไม่ได้: ข้อที่ตอบแล้วเก็บใน /v1/me/facts ใช้กับทุกรายการ

ใช้กับเหตุการณ์ชีวิตด้วย

ผู้ใช้เลือก "ถูกเลิกจ้าง / มีลูก / น้ำท่วม" ระบบรู้ว่าต้องเช็ครายการไหน แล้วเริ่มถามข้อแรกของรายการนั้น

🧮 Logic ตรวจย้อนได้

กฎเงินเป็นข้อมูลที่มีเวอร์ชันและแหล่งอ้างอิง ผลเหมือนเดิมทุกครั้ง อธิบายได้ว่าทำไม

🔗 เส้นทางเดียวจบ

รู้จัก → หาเงิน → อธิบาย → พาทำ → ติดตาม ใช้ข้อมูลชุดเดียวกัน ไม่ถามซ้ำ

🛡️ AI มีรั้ว 4 ชั้น

guard ก่อน LLM, เห็นแค่ข้อมูลผู้ใช้คนนั้น, ลบตัวเลขที่ไม่มีที่มา, ต้องยืนยันก่อนทำ

🔌 สลับแหล่งได้

10 adapters เปลี่ยนด้วย env แอปไม่รู้ว่าข้างหลังเป็น mock หรือของจริง

🏷️ ซื่อตรงกับข้อมูล

ทุกตัวเลขมี basis และป้ายระดับข้อมูล ไม่สัญญาเงิน ไม่แสดง mock เป็นของจริง

✅ ทนทาน

AI ล่ม → ใช้กฎ, กดซ้ำ → ไม่เกิดซ้ำ (Idempotency), error รูปเดียว, ไม่ให้ยินยอม → ยังใช้ได้บางส่วน
