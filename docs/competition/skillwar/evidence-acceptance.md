# หลักฐานตรวจรับสำหรับเป้า 100/100 ก่อนหัก

เป้าของทีมคือทำหลักฐานตามเกณฑ์ให้ครบ **25 ข้อ รวม 100 คะแนนก่อนหัก** ด้านล่างแยกสิ่งที่ตรวจซ้ำได้ออกจากส่วนที่กรรมการใช้ดุลยพินิจในแต่ละข้อ ให้ตรวจเงื่อนไขที่วัดได้แม้เป็นเกณฑ์ที่มีดุลยพินิจ เช่น คนดูใหม่ใช้เวลาเท่าไร แล้วคงคำตัดสินเรื่องความชัดหรือความแตกต่างไว้กับกรรมการ

ลงสถานะ **ผ่าน** เมื่อทุกเงื่อนไขที่วัดได้ในแถวนั้นมีหลักฐานและผู้ตรวจอีกคนทำซ้ำหรืออ่านผลได้ ใช้ **บางส่วน** เมื่อมีผลจริงแต่ขาดเงื่อนไข ใช้ **รอตรวจ** เมื่อหลักฐานที่ต้องใช้ยังไม่มี และใช้ **รอวันงาน** กับหลักฐานที่เกิดได้ในวันแข่งเท่านั้น ห้ามแปลงหลักฐานบางส่วนให้เป็นคะแนนเต็ม ค่าประเมินเดิม 58/100 ใช้ระบุช่องว่างเริ่มต้น [ใบประเมินเดิม](scorecard.md)

## ผลตรวจเพิ่มเติมจากระบบอ้างอิง

ซอร์สแอปและ backend ใช้ `8efb63b` เอกสารเปลี่ยนถึง `244c86e`. ทดสอบ provider ที่ตั้งค่าไว้ผ่าน HTTP loopback ด้วยโปรไฟล์สมมติและฐาน Demo แยกจากผู้ใช้จริง

| สิ่งที่ทดสอบ | สิ่งที่เกิดจริง | ผลต่อการตรวจรับ |
| --- | --- | --- |
| ค้นงานด้วยโปรไฟล์บางนา | `aiStatus: ok` โดยโมเดลส่ง `group: งาน` ไปที่ `search_opportunities` จึงคืน 0 รายการ | พบปัญหาค่าหมวด: tool ควรบังคับค่าที่ API รองรับ เช่น `job`, normalize ค่าที่รู้จัก และขอข้อมูลเพิ่มเมื่อแปลไม่ได้ |
| ค้นงานด้วยโปรไฟล์คลองสาน | `group: job` คืนรายการ mock และคำตอบสุดท้ายอยู่ใน `fallback_rules` รายการจำลองในข้อความขาดป้ายกำกับรายแถว | ใช้ตรวจ fallback ได้ ต้องแก้ป้าย provenance และทดสอบให้มีเทิร์น `ok` พร้อมผลที่อ้างกลับได้ |
| เก็บงานและ retry ผ่าน HTTP ในโหมด rules | ตัวอย่าง API 12 คำขอผ่าน บันทึกแล้ว event เดิมด้วย key เดิมเพิ่มความคืบหน้าเพียงครั้งเดียว | ใช้ยืนยันพฤติกรรม backend ของ action ได้ การตรวจจากผลสดในแชตต้องทำบน APK |
| ตรวจ Android บนเครื่องทดสอบ | `adb devices -l` ไม่มี device และ `flutter emulators` ไม่มี AVD | รออุปกรณ์เพื่อเก็บ C1–C5 |

หลักฐานแต่ละชิ้นให้ระบุข้อที่ครอบคลุม วันเวลา commit, build/provider, แหล่งข้อมูล, อินพุต, ผลจริง และชื่อผู้ตรวจ รอบต่อไปเริ่มจากแก้ค่าหมวดกับตัวกรองเขตและที่มารายรายการ แล้วตรวจเคสค้นเจอและกรณีผลว่างซ้ำบน build เดียวกัน ส่วน log ของ Kiro และฉบับส่งงานใช้หลักฐานจริงของวันที่ 30 พฤศจิกายน 2569 [แผนปิดช่องว่าง](gap-closure-plan.md)
