# แผนแก้ทางรอดเพื่อเก็บหลักฐานเต็ม 100 คะแนน

แก้เส้นเดียวก่อน **ข้อความไทย → ผลค้นงานที่มีที่มา → ยืนยันบันทึก → เปิดแผน** บนหน้าเดิม ชุดแก้แบ่งเป็น 3 commits ที่ตรวจและย้อนแยกได้ งานข้อมูล การซ้อม และ Pitch เดินคู่กัน ผู้ตรวจให้ผ่านทีละข้อตาม [ตารางหลักฐาน 25 ข้อ](evidence-acceptance.md)

## 1. แก้ตัวกรองตรงเครื่องมือค้นงานของแชต

ไฟล์หลักคือ `contracts/mock-server.js` ตรง `runAssistant` และ `search_opportunities` และเพิ่มเคสใน `contracts/test-thang-rot-guard.js`

1. ตอนแชตเข้าเส้นค้นงาน ให้ backend กำหนด `group=job` ก่อนเรียก `search()` เอง ให้โมเดลช่วยตีความคำค้นและเรียงผลจากรายการที่ได้รับ ค่า `group: งาน` จากโมเดลจึงไม่ทำให้ผลกลับเป็นว่าง ส่วนการเรียกเครื่องมือจาก intent อื่นใช้สัญญาเดิม
2. อ่านเขตจากข้อความที่ผ่าน guard ก่อนใช้เขตของโปรไฟล์เป็นค่าเริ่ม ใช้รายชื่อและรหัสเขตที่มีอยู่ แล้วส่ง `area=bangkok`, `district` และ `districtCode` เมื่อมี เก็บเฉพาะค่าที่ผ่านการตรวจแล้วไว้ในบริบทค้นงาน “ดูงานอื่น” ใช้บริบทเดียวกันและตัดรายการที่แสดงไปแล้ว เมื่อผู้ใช้เปลี่ยนเขตให้เริ่มชุดผลใหม่
3. ส่งทักษะและรูปแบบงานเมื่อระบุได้ชัด เวลาใช้ข้อมูลกะที่ประกาศมีอยู่ ถ้าเขตไม่ชัดหรือไม่พบงาน ให้ถามเพิ่มหรือเสนอขยายเงื่อนไขอย่างชัดเจน ให้ผู้ใช้เป็นคนเลือกก่อนค้นนอกเขต งานทางไกลขึ้นแยกเมื่อสอดคล้องกับคำขอ
4. ใช้ `search()` และตัวกรองเดิมต่อเพื่อรักษาการกรองประกาศปิด หมดอายุ เสี่ยง และลิงก์เสีย ให้ตัวเลือกใช้แหล่งจริงหรืออ้างอิงที่ตรวจแล้วมาจากขอบเขตข้อมูลที่ทีมใช้สาธิต เงื่อนไขรอบงานหลักใช้ `dataMode=real` ร่วมกับการตรวจแหล่งรายรายการจากงานข้อมูลด้านล่าง

**ผ่านเมื่อ** stub ส่ง `group: งาน` แล้วยังค้นในกลุ่มงานถูกต้อง เปลี่ยนบางนาเป็นอีกเขตแล้ว IDs เปลี่ยนตามข้อมูล “ดูงานอื่น” ยังอยู่ในเขตเดิม ผลว่างคงตัวกรองเดิม และเคสถามสิทธิหรือคำนวณรายได้เดิมผ่าน

## 2. ทำให้ผลทุกใบอ้างกลับได้และยืนยันบันทึกได้

ไฟล์หลักคือ `contracts/mock-server.js` และ `contracts/openapi.yaml` ใช้ `AgentTurn`, `pendingActions` และ `svc.createTask` ที่มีอยู่

1. หลัง search tool ทำงาน เก็บ IDs ที่คืนในรอบนั้น ให้ backend สร้าง `opportunityLinks` เป็น field เสริมใน `AgentTurn` สำหรับผลค้นงานเท่านั้น แต่ละรายการมี `opportunityId`, `title`, `dataStatus`, ข้อมูลเขตและ URL ต้นทางเมื่อมี ใช้ record จาก catalogue เป็นแหล่งของชื่อ จำนวนเงิน และลิงก์
2. ให้รายการที่บันทึกได้ชี้ `actionId` ใน `pendingActions` ของรายการเดียวกัน Backend สร้างข้อเสนอบันทึกจาก ID ที่ผ่านการตรวจ ให้โมเดลเลือกหรือเรียงจาก IDs ที่เครื่องมือคืนได้ ตรวจ ID ซ้ำตอนยืนยันเมื่อแหล่งหรือสถานะเปลี่ยน และใช้ปลายทาง confirm/reject เดิม
3. สำหรับผลค้นงาน ให้ข้อความประกอบอธิบายเงื่อนไขหรือเหตุที่ผลว่าง ใช้ชื่อ ค่าจ้าง ป้าย mock และลิงก์จากรายการที่ backend ตรวจแล้ว ให้ข้อความยืนยันการสมัคร บันทึก หรือตั้งแจ้งเตือนเกิดตามผล action จริง ใช้กติกานี้ทั้งผลจาก provider และ fallback
4. เก็บหลักฐานที่เห็น tool และ IDs จากรอบซ้อมในเครื่อง ใช้ response กับบันทึกที่ตัดข้อมูลส่วนบุคคลออก Field `aiStatus` คงความหมายเดิม ถ้า fallback ให้แสดงเป็น fallback

**ผ่านเมื่อ** โมเดลเสนอ ID ที่ไม่อยู่ในผลค้นแล้วไม่มีการ์ดหรือ action ของ ID นั้น ทุก mock มีป้าย เมื่อ reject ข้อมูลคงเดิม confirm ซ้ำแล้ว task เดียว ลิงก์เปิดได้หรือแจ้งว่าไม่พร้อม และ `AgentTurn` เดิมที่ไม่มี field เสริมยังตรวจ schema ผ่าน

## 3. เพิ่มลิงก์กับปุ่มเดิมลงในแชต

ไฟล์หลักคือ `app/lib/chat.dart` และชุดทดสอบแชตเดิม

1. อ่าน `opportunityLinks` แบบ optional แสดงชื่อ เขต และป้ายแหล่งข้อมูลเป็นแถวกดดูต้นทาง ใช้ `openExternal` ที่มีอยู่และปิดคำถามยืนยันการสมัครหลังเปิดลิงก์อ้างอิง
2. ใช้ปุ่มยืนยันและโค้ด `_decide` เดิมสำหรับ `actionId` ที่จับคู่ได้ เมื่อบันทึกสำเร็จใช้ปุ่ม “ดูแผนของฉัน” เดิม ถ้าเปิดจากโปรไฟล์ Demo ให้ตรวจ routing ของแผนด้วย device scope เดิม เมื่อ field ใหม่ไม่มา แชตยังแสดงข้อความและปุ่มเก่าตามปกติ
3. ใช้สถานะส่งข้อความและลองใหม่เดิม จับกรณีเน็ตหลุดหลังยืนยันให้ลอง action เดิมด้วย ID เดิม ผลต้องคืนแผนเดียว หากการทดสอบขั้นต่อไปในหน้าแผนพบการกดซ้ำหลัง timeout ให้แก้เฉพาะการใช้ idempotency key ซ้ำของ event นั้นใน commit แยก

**ผ่านเมื่อ** เปิดต้นทาง HTTP(S) จากแถวเดียวกับที่บันทึกได้ทั้งโหมดปกติและ mock อีกทั้งใช้ client กับ response เก่าได้ ใช้ server กับ client เก่าได้ และหน้าแผนเปิดได้หลังออกจากแชต

## งานที่ปิดคะแนนได้โดยไม่แก้แอปเพิ่ม

| งาน | ใครทำ | หลักฐานที่ใช้ตรวจ |
| --- | --- | --- |
| ตรวจรายการจริง | ข้อมูล | เลือกข้อมูลสำหรับเคสค้นเจอและเคสเปลี่ยนเงื่อนไข เปิดต้นทางจากมือถือ เก็บวันตรวจ เขต สถานะ และสิทธิใช้ข้อมูล แยกประกาศออกจากหน้าบริการหางานภาครัฐ ตรวจซ้ำวันแข่ง |
| รันเส้นหลักและทางกู้ | QA และ Flutter | บนอุปกรณ์เดียวกันเก็บวิดีโอค้นเจอและบันทึก, เปลี่ยนเงื่อนไขและดูงานอื่น, no-match, provider timeout และ source เปิดไม่ได้ บันทึกผล API กับ SHA เดียวกับ APK |
| ตรวจการนำเสนอและการใช้งาน | QA และ Pitch | ให้คนใหม่ทำเส้นหลักและดูช่วง 2 นาทีแรก เก็บผลจอเล็ก ตัวอักษรขยาย และ HDMI ซ้อม 7 นาทีและเก็บเสถียรภาพครบ 10 นาที |
| ปิดหลักฐานโจทย์และธุรกิจ | Product และ Pitch | แหล่งข้อมูลปัญหาของ persona, เปรียบเทียบขั้นตอนกับช่องทางเดิม, เหตุผลที่ AI ช่วย, ธีมทั้งสอง และแผน pilot ที่มีเจ้าของกับตัวชี้วัด ตรวจเด็คจริงไม่เกิน 8 หน้าเนื้อหา |
| เก็บหลักฐานวันแข่ง | ผู้ดูแล Kiro และผู้ส่งงาน | Activity Log JSON จากงาน AI และการทดสอบจริง เชื่อม commit, build, วิดีโอสำรอง และชุดส่งของวันแข่ง |

## ตรวจผลกระทบก่อนรับแต่ละ commit

- เริ่มจาก baseline ที่ตรวจล่าสุด `npm.cmd --prefix contracts test` ผ่าน 248/248 checks ครบ 50 operations. เทียบกับผลหลังเปลี่ยน และรัน `node contracts/test-thang-rot-guard.js`, `node contracts/test-thang-rot-manual.js`, `flutter test` และ `flutter analyze`
- ทวนเส้นเดิม **ค้นโอกาสจากแท็บ, เช็กสิทธิ, วางแผนรายได้, เปิดแผนเก่า, ยกเลิก action, โหมดไม่มี AI consent** แล้วตรวจ source/status ของแชตทั้งแบบ live กับ fallback
- ตรวจความเข้ากันได้สองทางของ field ใหม่และสถานะที่เก็บไว้เดิม ชุดแก้เปลี่ยนเฉพาะแชตค้นงานและใช้ API paths, หน้าจอหลัก, ฐานข้อมูล และ state layout เดิม หากชุดใดทำให้เทสต์เดิมตก ให้ย้อนเฉพาะชุดนั้นและเก็บผลที่ต่างกันไว้ตรวจ
- รอบซ้อมที่ผ่านต้องมี `aiStatus: ok` และ search tool คืนอย่างน้อยหนึ่ง ID ที่มีต้นทางจริง พร้อมกดยืนยันแล้วเปิดแผนได้ เคส mock, no-match และ fallback ใช้พิสูจน์ชุดทดสอบของตัวเอง
- เมื่อหลักฐานวัดได้ครบ 25 ข้อ ให้ปิดรายการตาม [ตารางตรวจรับ](evidence-acceptance.md) หลักฐานที่เกิดเฉพาะวันแข่งยังต้องเก็บตามตาราง ส่วนคำตัดสินเชิงคุณภาพเป็นของกรรมการ

ลำดับตรวจคือ **ข้อมูลจริงและชุดแก้ 1 → ผลที่อ้างกลับได้ในชุดแก้ 2 → Android ในชุดแก้ 3 → ซ้อมและปิดตารางหลักฐาน** จากนั้นค่อยกลับไปอัปเดตข้อ 2 และ 3 ของงานเดิมตามพฤติกรรมที่ตรวจแล้ว
